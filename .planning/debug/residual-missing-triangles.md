## Current Focus

- **ROOT CAUSE FOUND (2026-09-19):** `CSRasterizeVertexColors` rejects triangles as "degenerate" via `abs(denom) < NAMER_DECOMP_AREA_EPS` with `denom = d00*d11 - d01*d01 = (2·Area_UV)²` — QUADRATIC in UV edge length. UVs are [0,1] on a 2048² atlas, so a healthy ~73-texel² triangle has `denom ≈ 1.2e-9 < 1e-8` and is DISCARDED. Measured on the real mesh: **12,022 / 13,082 triangles (91.9%) fall below the gate**; removing the gate, **all 13,082 centroids pass the inside-test**. Only triangles ≥ ~210 texel² area rasterize; all smaller ones fall to the uncovered branch → `_VcInterp = (0,0,0,0)` → `CSResidual` writes identity 1.0 → no correcting signal. The user's dark-vertex correlation was coincidental (dark geometry lives in the same border bands).
- **fix proposal (checkpointed, not yet applied):** do the barycentric test in TEXEL space in `NAMERDecomp.compute` — multiply the three `_Uvs` verts by `_Size` and use texel-center point `(id.xy + 0.5)` directly (4-line change at lines 98/102-104). Then `denom` is `(2·Area_texels)²`, and `1e-8` once again means "smaller than any representable real triangle" (1-texel² → denom ≈ 4) while exact zero-area degenerates are still rejected. Barycentric ratios and `NAMER_DECOMP_INSIDE_EPS` are dimensionless — unchanged.
- **adjacent (out of scope, flagged):** `NamerAOBaker.TryReconstruct` (NamerAOBaker.cs:373) has the same UV-space `1e-8` skip — latent twin bug for AO reconstruction on small triangles. `VertexColorFitter.Solve3x3` (VertexColorFitter.cs:283) is NOT affected: its gate is on the 3×3 Gram determinant with a jitter-and-still-solve fallback, which is why the vertex-color fit itself is correct.
- **next_action:** User approves fix → apply kernel change → pin with small-UV-triangle EditMode regression test → re-run real-asset classifier (expect identityAbsent ≈ 0) → user re-runs Process with NAMER for visual confirmation.
