## Resolution

root_cause: "SourceInspector.CollectMaterials routes ANY selection that is not a Material/GameObject/folder but has a non-empty AssetDatabase.GetAssetPath into the catch-all branch (SourceInspector.cs:246-251) and passes the path unvalidated to AddSubAssetMaterials -> AssetDatabase.LoadAllAssetsAtPath (line 291). When the editor's active selection is a scene asset (SceneAsset, path '*.unity'), Unity's threaded sub-asset reader rejects scene files and logs 'Do not use ReadObjectThreaded on scene objects!' with exactly the reported stack. The defect is a missing asset-kind guard on every LoadAllAssetsAtPath call site reachable from a user selection. IMPORTANT CORRECTION to the UAT premise: selecting a scene-instance GameObject does NOT trigger this — GetAssetPath returns '' for scene objects and the existing guard (lines 190-198) handles them safely and read-only; the stack's line 248 (catch-all, non-GameObject branch — verified against all 6 historical versions of the file) proves the failing selection was a non-GameObject asset whose path is a .unity scene. The 'scene object not visible' report is separate from the exception: the entire selection->inspection->preview chain is provably read-only (no hideFlags/SetActive/layer/material mutation on the selection), so selection cannot hide anything; the only scene-instance mutation in the package is NamerProcessor.BindGeneratedMaterials (Process-triggered mesh+material swap), and if the object truly vanished from the Scene view the suspect is the generated split mesh / NAMER material bound by Test 4's Process run — needs live verification; if 'not visible' refers to the NAMER window it is the direct cosmetic consequence of this same bug (empty inspection -> 'No materials found' / 'No mesh to preview', plus a second identical error from NamerEditorWindow.FindMeshSubAsset:1190)."
fix: "(diagnose-only session — direction for plan-phase --gaps) Minimal guard on asset kind before LoadAllAssetsAtPath: (1) in SourceInspector.CollectMaterials' catch-all branch (before line 248), treat a .unity path (or AssetDatabase.LoadMainAssetAtPath(path) is SceneAsset) as unsupported and add a warning mirroring line 253's style ('Unsupported selection: select a project asset ...'); same guard ideally at the top of AddSubAssetMaterials as the choke point.
