## Symptoms

- **Expected:** With vertex color + residual, albedo reconstruction should visually match the source base color, especially at the white patch on the brown (leather) jacket; user needs to isolate Base color texture vs Vertex Coloring inputs to debug each mapping; a triangle mesh overlay would help; re-processing with decomposition off should render base-only.
- **Actual:** VC + residual "isn't recreating the original base color... especially noticeable around the patch on the jacket (white surrounded by brown)"; user hypothesizes spanning triangles use one color for all 3 points instead of a gradient. Additionally: with only AO checked and Write Residual + Decomposition unchecked, the rendered model still shows the stale smeared look (albedo = base × stale vertex colors), and shaded-view toggles "change almost nothing".
- **Errors:** None (visual defect, no exceptions).
- **Timeline:** Since the 04.2 UAT runs on 2026-09-18 (11:36 decomp-on/WriteResidual-on run; ~12:06 decomp-on/WriteResidual-off run; 12:07 decomp-off run).
- **Reproduction:** Process with decomposition on → observe patch reconstruction failure; re-process with decomposition off → split mesh keeps previously fitted colors (mesh write skipped) while .mat re-binds Base.png → albedo = base × stale vc double application.

## Current Focus

- **hypothesis:** (A) Patch failure: VertexColorFitter solves a true 3-corner gradient per triangle but `VertexColorFitter.cs:184-187` + `SolveAndAccumulate` average all incident triangles' corner-solves into each shared vertex (weight 1 each), muddying boundary vertices toward the middle → spanning triangles near-flat; the residual cancels this per-texel in texture space, but at render the sharp quotient edge at the patch frays under bilinear no-mip EXR sampling vs screen-space vc interpolation. User needs the isolation toggles + triangle overlay to see which term fails. (B) Stale-mesh: NamerProcessor.cs gates ALL mesh writes on DecompositionEnabled (~line 185) and AssetGenerator.Generate only calls WriteMeshAsset when decomp != null (AssetGenerator.cs:180-188, D-06), so a decomp-off reprocess never clears/overwrites the previously fitted colors on the existing generated mesh asset.
- **test:** Disk identity already verified: Base.png × Residual.exr ≈ source in linear (p90 0.014, 99.3% of texels within 0.05; worst errors in dark low-vc quotient-blowup regions). Live state measured: mesh colors min(0,0,0) max(202,143,155) 0% white; .mat binds Base PNG guid 7974d991 at _BaseResidualMap; gate floats on the persistent scene material instance read DbgResidual=0/DbgAO=1 (ApplyDebugGates does reach the scene instance).
- **expecting:** After the three fixes: (1) toggling "Vertex Color" off neutralizes the vertexColor term and "Base/Residual" off neutralizes the sampled map term in the shaded view, letting the user isolate each input; (2) a "Triangles" toggle overlays the split-mesh wireframe on the After preview; (3) a decomp-off reprocess produces base-only rendering (mesh colors no longer double-applied).
