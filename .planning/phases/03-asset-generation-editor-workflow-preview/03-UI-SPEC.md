# Phase 3 — UI Design Contract

> Visual and interaction contract for the `Tools > NAMER > Processor` editor window (and its two context-menu entry points). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a Unity Editor plugin, not a web frontend.** The "design system" is Unity's native editor chrome (IMGUI + `GUISkin`/`EditorStyles`). No shadcn, no CSS, no external component/icon library. Every token below is expressed in Unity Editor terms (`EditorGUILayout`, `HelpBox`, `Toolbar`, `PreviewRenderUtility`) and inherits Unity's native look (`EditorGUIUtility.isProSkin`), so the window reads as a first-party Unity inspector rather than a parallel design system.

| Property | Value |

## Spacing Scale

Spacing follows Unity's native IMGUI metrics for intra-row rhythm and a 4-multiple scale for the section-level gaps the window owns. Do **not** hand-tune `EditorGUIUtility.standardVerticalSpacing`; rely on the native values except where a token below calls for an explicit `EditorGUILayout.Space()` / `GUILayout.Space()`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 2px | Unity native `EditorGUIUtility.standardVerticalSpacing` — vertical gap between controls (leave at default) |
| sm | 4px | Horizontal gap between a field label and its control (`EditorGUIUtility.labelWidth` + 4px); space between a HelpBox and the next control |
| md | 8px | Gap between control groups inside a section; padding around warning/error HelpBox lists |
| lg | 16px | Vertical separation between sections (Source → Preview → Processing → Output → Action) |
| xl | 24px | Gutter between the before/after preview panes; padding inside the preview box |
| 2xl | 32px | Window-edge padding (top/bottom of the scrollable content) |
| 3xl | 64px | Not used this phase |

**Exceptions:** `xs = 2px` is Unity's native baseline (`standardVerticalSpacing`), intentionally kept (not a 4-multiple) so the window matches stock editor rhythm. All section-level gaps (sm…2xl) are multiples of 4.

## Typography

Four roles, three sizes, two weights. All styles are `EditorStyles`/`GUISkin` built-ins or trivial bold variants — never a custom font import.

| Role | Size | Weight | Line Height | Unity Style |
|------|------|--------|-------------|-------------|
| Helper | 11px | regular (400) | 1.4 (14px) | `EditorStyles.miniLabel` — status line, hints, secondary caption text |
| Body | 12px | regular (400) | 1.5 (18px) | `EditorStyles.label` — inspection summary, HelpBox copy, field values |
| Label | 12px | regular (400) | 1.5 (18px) | `EditorStyles.label` — field labels, toolbar item captions |
| Heading | 12px | bold (700) | 1.5 (18px) | `EditorStyles.boldLabel` — section headers |
| Display | 16px | regular (400) | 1.25 (20px) | `EditorStyles.largeLabel` — empty-state heading, "Before"/"After" preview captions |

- Line heights are governed by `EditorGUIUtility.singleLineHeight` (default 18px at 12px body → ratio 1.5); do not set explicit line heights — express them as the ratios above.
- Exactly two weights: **regular (400)** and **bold (700)**. No medium/semibold variants.

## Color

Colors are inherited from Unity's editor skin (`GUI.skin` + `EditorGUIUtility.isProSkin`) — **never hard-coded**. Representative hexes below document the dark/light appearance for reference only; the implementation reads from the skin.

| Role | Source (single truth) | Representative hex (dark / light) | Usage |
|------|----------------------|-----------------------------------|-------|
| Dominant (60%) | `GUISkin.window` background | `#383838` / `#C8C8C8` | Window and preview-pane background |
| Secondary (30%) | `EditorStyles` field/box backgrounds | `#2C2C2C` / `#F0F0F0` | Section boxes, preview pane framing, HelpBox surfaces, field backgrounds |
| Accent (10%) | Unity selection/focus blue (`GUI.skin.settings.selectionColor` + focus) | `#007ACC` / `#007ACC` | Primary CTA focus/active, active debug-channel toolbar item, focused field outline |
| Destructive | HelpBox error color | `#CC3333` / `#CC3333` | Error HelpBox, overwrite-refusal message, readback-failed status |

**Accent reserved for (explicit list — never arbitrary decoration):**
1. The **"Process with NAMER"** primary button's focused/active state.
2. The **active (selected) debug-channel toolbar** item.
3. The **focused field** outline on destination / prefix / suffix.

Not reserved for: field labels, section headings, preview-pane borders, or summary text.

**Destructive reserved for (explicit list):**
1. **Overwrite-refusal** error HelpBox (D-04: non-stamped collision).
2. **Readback-failed** error status (`request.hasError`).
3. **Unsupported/empty selection** blocking errors.

No other element uses the destructive color.

## Layout

Section order (top → bottom), fixed for this phase:

1. **Source** — selection name/path + inspection summary + warning HelpBox list.
2. **Preview** — before/after panes side-by-side (xl gutter), "Before"/"After" captions above each pane, debug-channel `Toolbar` beneath the after pane.
3. **Processing** — AO un-multiply strength slider + numeric readout.
4. **Output** — destination folder field, prefix field, suffix field, overwrite-generated toggle (a compact 2×2 or stacked field group).
5. **Action** — "Process with NAMER" button + status line/HelpBox.

Rationale (Claude's discretion, grounded in D-14's control set): source state first, the dominant visual (preview) second, the control that re-renders the preview (AO strength) next to it, then output configuration, then the explicit write action at the bottom. The whole window scrolls (`EditorGUILayout.ScrollView` is acceptable but not required if the panel is compact).

## Interaction Contract

- **AO strength change → debounced recompute (UI-06):** mark dirty; after **300 ms** of no further change, re-run `NamerComputePipeline.Process` → `AsyncGPUReadback` → on completion `Repaint()`. **Never writes to disk** (D-10). Debounce interval is a named constant (`kDebounceSeconds = 0.3f`), not a magic number.
- **Process click → write:** validate selection → `SourceInspector.Inspect` → `NamerComputePipeline.Process` → readback → `AssetGenerator` writes PNGs + material + stamps importer + labels (the only disk writer). Button label switches to "Processing…" and is disabled for the duration.
- **Preview camera:** single synced camera state shared by both panes (honest lighting/angle comparison, D-09). Orbit/zoom via mouse drag inside the preview box; framing re-centers on selection change.
- **Debug channel picker:** switches only the **after** pane. "Shaded" (default) renders the real NAMER material; the six channel modes render the editor-only debug shader (`_DebugChannel` 0–5). The **before** pane always renders the source material, never a debug channel.
- **Disabled states:** Process button disabled when Empty, Inspecting, Recomputing, or Busy; debug toolbar disabled when Empty or Busy; AO slider disabled when no material or Busy. **No dead controls** — every visible control is functional this phase (D-14).
- **Overwrite (D-04):** enabling "Overwrite generated" permits overwriting only `NamerGenerated`-stamped assets inside the destination. A collision with a non-stamped file aborts with a blocking error HelpBox, not a dialog (see Copywriting).

## State Contract

| State | Trigger | UI behavior |
|-------|---------|-------------|
| Empty | No selection | Source display shows "—"; preview shows empty-state heading + body; Process disabled |
| Inspecting | Selection changed | Source display refreshes; summary rebuilds from `NamerSourceModel`; Process disabled until ready |
| Ready | Valid inspection + preview rendered | All controls enabled; Process enabled |
| Recomputing | AO strength change (debounce) | Debug toolbar + AO slider stay enabled; Process disabled; preview shows previous frame until readback completes |
| Busy / Processing | Process clicked | Button reads "Processing…"; all controls disabled; status line "Processing {n} material(s)…" |
| Success | Writes complete | Status: "Generated {n} material(s) under {destination}."; controls re-enabled |
| Error | `request.hasError`, overwrite refusal, or unsupported selection | Error HelpBox (destructive color); controls re-enabled; no assets written |

## Debug Channel Contract

The debug picker has **7 modes** — the lit NAMER view plus the six channels derivable this phase (D-11). The debug shader (`NamerDebugView.shader`) must `#include "NamerSurface.hlsl"` and call `NAMER_DECODE_SURFACE` so views cannot drift from the runtime decode (D-12).

| UI label | Mode | `_DebugChannel` | Renders |
|----------|------|-----------------|---------|
| Shaded | runtime NAMER material (default) | n/a (not the debug shader) | lit NAMER result |
| Base Color | debug | 0 | reconstructed/normalized base color |
| AO | debug | 1 | occlusion |
| Normal | debug | 2 | decoded octahedral normal |
| Roughness | debug | 3 | roughness (6-bit decoded) |
| Metallic | debug | 4 | metallic flag |
| Emissive | debug | 5 | emissive flag |

Vertex-color, residual, and reconstruction-error views are **Phase 4** — no stub toggles, no disabled placeholder entries (D-11).
