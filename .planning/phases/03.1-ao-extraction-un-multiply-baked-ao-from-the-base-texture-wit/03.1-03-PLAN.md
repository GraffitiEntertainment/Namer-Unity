<objective>
Expose the three AO-shaping controls (blur radius, strength, contrast) and the optional high-res occluder field in the existing Processing section, and wire them through EditorPrefs-backed settings into the AO pipeline so they shape AO regardless of source (D-11). The controls persist across sessions (D-13) and debounce-recompute in memory exactly like `AoUnmultiplyStrength` (D-10). The occluder field overrides the bake source (D-04); a null/invalid assignment warns visibly and falls back to the selected mesh (D-06). The window also becomes the AUTOMATIC trigger for the geometry bake: after each recompute, when the source has no authored `_OcclusionMap`, a bake-capable mesh, and no cached bake, it calls `NamerComputePipeline.RequestBake` (off the 300 ms debounce, cached + async) and re-dirties the preview when the bake lands. Only functionally-required controls ship — no dead bake knobs like direction count or ray distance (D-12).

Purpose: Make the AO pipeline artist-tunable, make the high->low bake override usable, and close the automatic-trigger loop so the bake is not only routable (03.1-02) but actually invoked.

Output: edits to `Editor/NamerEditorConstants.cs`, `Editor/Settings/NamerProcessorSettings.cs`, `Editor/Pipeline/NamerSourceModel.cs`, `Editor/Pipeline/NamerAOPipeline.cs`, `Editor/UI/NamerEditorWindow.cs`, and `Tests/Editor/NamerAOControlsTests.cs`.
