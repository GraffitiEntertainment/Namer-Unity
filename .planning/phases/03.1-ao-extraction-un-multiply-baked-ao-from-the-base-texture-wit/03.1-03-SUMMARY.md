# Phase 03.1 Plan 03: AO Tweak Controls + Occluder Override + Automatic Bake Trigger Summary

Artist-tunable AO blur/strength/contrast sliders and a high-res occluder override shape AO regardless of source (extracted or baked) via a source-agnostic GPU tweak stage, persist through EditorPrefs, and drive an automatic geometry-bake trigger that closes the Phase 03.1 loop.

## Accomplishments

- Wired the three AO-shaping controls (`AoBlurRadius`/`AoStrength`/`AoContrast`) from EditorPrefs-backed `NamerProcessorSettings` into `NamerMaterialInspection` and a source-agnostic `strength -> contrast -> user-blur` stage in `NamerAOPipeline` — applied to both extracted AO (after the internal low-pass) and baked AO (after JFA dilation), so the same sliders shape AO regardless of source (D-11).
- Added the Processing-section sliders (blur 0..16, strength 0..1, contrast 0..4) and the optional "High-res Occluder" field, all debounce-recomputing in memory like `AoUnmultiplyStrength` (D-10/D-13); an invalid occluder warns via `HelpBox` and falls back to the selected mesh (D-04/D-06).
- Closed the automatic-trigger loop: `RecomputePreview` now calls `NamerComputePipeline.RequestBake` (cached + idempotent) when a mesh-backed source has no authored `_OcclusionMap` and no cached bake, re-dirtying the preview when the bake lands (D-07).
- Four new tests (kernel-level strength/contrast semantics, EditorPrefs persistence with snapshot/restore, single-un-multiply-gate reflection check) bring the EditMode suite to 72/72 green in the clone runner.
