# Phase 03.1: AO Extraction - Context

**Gathered:** 2026-08-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver real AO to the packed surface B channel and un-multiply baked AO out of the base color, via **two AO sources landing in this one phase** (user decision — the defer recommendation was explicitly overridden):

1. **Image-space extraction** — estimate the AO baked into the base texture (Tripo sources bake AO into base color with no `_OcclusionMap`), so `AoUnmultiplyStrength` stops being a mathematical no-op.
2. **Geometry bake ("cubemap of light")** — multi-directional visibility bake from mesh geometry, high-res→low-res, matching the Blender reference workflow.

Both feed the existing pipeline: extracted/baked AO is the un-multiply divisor in `CSNormalize` AND the packed surface B channel. No new output assets — AO lives only in B. The Phase 1 format contract and the runtime decode are untouched.

**Out of boundary:** composite/blended AO ops (Phase 5 painted AO), edge-preserving blur (Phase 5 STYL-04), separate AO texture output.

</domain>

<decisions>
## Implementation Decisions

### AO source strategy
- **D-01:** BOTH sources land this phase — image-space extraction AND the geometry bake. User overrode the research recommendation to defer the bake; the bake is named in the phase title and is in scope.
- **D-02:** Within-phase sequencing: deliver image-space extraction first (it fixes the urgent live pain — dead slider, always-white AO), geometry bake second. Waves should order so the un-multiply works end-to-end even if the bake needs iteration.

### High-res model input (bake source)
- **D-03:** Selected mesh is the default bake source — zero new required UI, guaranteed spatial/UV coherence.
- **D-04:** An OPTIONAL user-assigned high-res mesh overrides the occluder. The high-res mesh is a geometry **occluder only**: rays originate on the selected mesh's texels, output UVs stay the selected mesh's, so the high-res field needs **no UV match** — only spatial overlap with the processed mesh. (This is the standard high→low bake model and is what makes the override coherent.)
- **D-05:** Bake parameters carried over from the Blender reference (`ao_operators.py`), as defaults:
  - **Cage/ray-start offset: 0.01** along the texel normal — prevents the high-res surface from self-occluding at zero distance (reference `cage_extrusion` "Extend Cage Out By", `properties.py` default 0.01; user specifically remembered and requested this detail be preserved).
  - **Max ray distance: 10% of the selected mesh's largest bounds dimension**, auto-derived, not a user knob (reference `light_settings.distance = model_size * 0.1`).
  - **64 ray directions** (reference Cycles samples = 64).
  - **16 px UV-seam dilation** of the baked AO (reference bake margin = 16).
- **D-06:** Invalid/missing occluder assignment falls back to the selected mesh with a visible warning, never a hard failure.

### Output combination
- **D-07:** Single AO source, automatic: an authored `_OcclusionMap` wins when present (byte-identical to today's behavior); extraction/bake runs automatically only when the map is absent. No new mode toggle.
- **D-08:** The SAME AO value is both the un-multiply divisor in `CSNormalize` and the packed B channel — round-trip `base_unmul × ao_packed ≈ base` holds by construction at strength 1.0. No double-darkening.
- **D-09:** For extracted/baked AO, floor the un-multiply divisor at **0.1** (reference `remove_ao_from_texture` clips AO to [0.1, 1.0] before dividing) rather than raw `NAMER_EPSILON`. Keeps un-multiply behavior reference-compatible and caps un-multiply darkening at 10%.
- **D-10:** `AoUnmultiplyStrength` (0 = off) remains the only on/off gate for the un-multiply; no additional toggle.

### Bake tweak controls
- **D-11:** New controls: **AO blur radius** (plain gaussian — edge-preserving is Phase 5 STYL-04) + **AO strength** + **AO contrast**, alongside the existing un-multiply slider. These shape the AO output regardless of source (applied to both image-extracted and baked AO).
- **D-12:** The geometry bake exposes only functionally required parameters (D-14 of Phase 03: no dead UI) — e.g. cage offset default 0.01 is exposed only if the planner finds it needs adjustment in practice; ray distance and direction count stay auto-derived defaults.
- **D-13:** All controls live in the existing Processing section, debounced interactive recompute (D-10 of Phase 03), EditorPrefs-persisted via `NamerProcessorSettings` (D-03 of Phase 03).

### Claude's Discretion
- Implementation route for the geometry bake: CPU Burst raycast (Unity.Mathematics + Collections, per-texel 64-direction visibility) with results uploaded as a StructuredBuffer, or GPU depth-projection (render occluder depth from N directions, project texels). Compute shaders cannot raycast mesh data directly; pick the route research supports, favoring Burst for determinism/testability.
- Image-space extraction algorithm details (low-frequency decomposition method, blur separability, halo mitigation between blur and divide ordering).
- Kernel/file decomposition (extend `NAMERPack.compute` vs new `NAMERAO.compute`).
- UI layout of the new controls within the Processing section.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `NamerComputePipeline`: RT pool, per-call uploads, dispatch harness, `RawCopyMaterial()`/`ReencodeSrgbKeyword` raw-copy pattern — extend for new AO kernels.
- `NamerComputeResult` + `ReleaseResult` pooling contract — add AO intermediate targets through the same pool.
- `NamerProcessorSettings` (EditorPrefs) + debounced `MarkDirty`/`Tick`/`RecomputePreview` path — new controls plug in exactly like `AoUnmultiplyStrength`.
- Debug channel toolbar already has an "AO" view (index 2) sharing `NAMER_DECODE_SURFACE` — extracted/baked AO becomes immediately inspectable there.
- `ResolvePreviewMesh` (NamerEditorWindow) — mesh resolution logic reusable for the default bake source.
- Unity.Mathematics (no SVD needed here) + Burst + Collections — the sanctioned stack if the CPU raycast route is chosen.

### Established Patterns
- GPU compute for all per-pixel work; no per-pixel C# loops on textures (project constraint).
- Interactive preview is memory-only (D-10); disk writes only from `AssetGenerator`.
- Settings flow: `NamerProcessorSettings` field → window control → inspection/kernel uniform.

### Integration Points
- `SourceInspector`/`NamerMaterialInspection`: `_OcclusionMap` presence is the D-07 gate.
- `CSNormalize`: the un-multiply divide — the extracted/baked AO texture replaces the white fill as `_AoIn` when no authored map exists.
- Surface pack kernel: B channel takes the same AO value (D-08).
- `AssetGenerator.WriteMaterial`: `_OcclusionStrength` metadata already carries; no format change.
