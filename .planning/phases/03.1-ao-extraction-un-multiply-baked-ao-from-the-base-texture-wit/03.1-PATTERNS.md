**Kernel pragmas / RWTexture / uniforms** (lines 18-43):
```hlsl

#pragma kernel CSOctahedralEncode
#pragma kernel CSSurfacePack

// Kernel-written outputs (linear, random-access).

// ...
// Blit-uploaded inputs (never written by kernels).

// ...

// ...
```

**Kernel body guard + `[numthreads(8,8,1)]`** (lines 45-56):
```hlsl
[numthreads(8,8,1)]
void CSNormalize(uint3 id : SV_DispatchThreadID)
{
    if (id.x >= _Size.x || id.y >= _Size.y)
    {
        return;
    }

    float4 baseColorIn = _BaseColorIn[id.xy];
    float3 base = (_SourceIsSrgb > 0.5) ? SRGBToLinear(baseColorIn.rgb) : baseColorIn.rgb;
    float ao = _AoIn[id.xy].g;
    _BaseColorOut[id.xy] = float4(base / lerp(1.0, max(ao, NAMER_EPSILON), _AoUnmultiplyStrength), 1.0);
```
Copy the same `uint3 id : SV_DispatchThreadID` + `if (id.x >= _Size.x ...) return;` guard and `[numthreads(8,8,1)]` on every new AO kernel. The RESEARCH Pattern 1 separable blur (lines 143-159 of RESEARCH.md) is the same shape: no `groupshared`, neighbor reads clamped to `_Size`.

**Dispatch harness** — `Editor/Pipeline/NamerComputePipeline.cs` lines 211-214:
```csharp
private void Dispatch(int kernel, int w, int h)
{
    _compute.Dispatch(kernel, (w + 7) / 8, (h + 7) / 8, 1);
}
```
`NamerAOPipeline` dispatches AO kernels with this exact `(w + 7) / 8` threadgroup math.

## Shared Patterns

### AO green-channel contract (applies to all new AO writers)
**Source:** `Compute/NAMERPack.compute` lines 55, 96, 108
```hlsl
float ao = _AoIn[id.xy].g;                                   // CSNormalize reads .g
_Octahedral[id.xy] = float4(oct, _AoIn[id.xy].g, 0.0);       // CSOctahedralEncode reads .g
float ao = _Octahedral[id.xy].b;                             // CSSurfacePack B = AO
```
Every new AO texture MUST write AO into the **green** channel (or grayscale) or `_AoIn.g` reads ~0 (RESEARCH Pitfall 1). The AO intermediate is `R8G8B8A8_UNorm` **linear** — never sRGB (Pitfall 2).

### sRGB/linear raw-copy upload contract (applies to `NamerAOPipeline`, bake upload)
**Source:** `NamerComputePipeline.Upload` lines 221-246 + `NamerRawCopy.shader` lines 61-75
```csharp
bool reencode = GraphicsFormatUtility.IsSRGBFormat(upload.graphicsFormat)
    && QualitySettings.activeColorSpace == ColorSpace.Linear;
```
```hlsl
float3 NamerLinearToSRGB(float3 c)
{
    c = max(c, 0.0.xxx);
    return c <= 0.0031308.xxx ? c * 12.92 : 1.055 * pow(c, 1.0 / 2.4) - 0.055;
}
```
Uploads go through `Graphics.Blit(source, target, RawCopyMaterial())` with the `_REENCODE_SRGB` keyword toggled, never `Graphics.CopyTexture` (mip/format-restricted).

### Mirrored-constants pattern (applies to `NamerConstants.cs` + `NamerEncode.hlsl` + `NAMERAO.hlsl`)
**Source:** `Core/NamerConstants.cs` lines 9-34 ↔ `Compute/NamerEncode.hlsl` lines 14-21
`NAMER_AO_FLOOR = 0.1` must be added in **both** the C# `NamerConstants` (as `AoFloor`) and the HLSL include (as `static const float NAMER_AO_FLOOR`), keeping the "mirrored manually" doc comment. The `0.1` floor is divisor-side only (RESEARCH Pitfall 3).

### Runtime decode do-not-break (applies to `NAMERPack.compute`, `NamerComputePipeline` edits)
**Source:** `Shaders/NamerSurface.hlsl` line 73
```hlsl

```
Do NOT change the B channel storage or `_OcclusionStrength` metadata; the new processing-time "AO strength" control is a distinct `NamerProcessorSettings` field (RESEARCH Pitfall 6).
