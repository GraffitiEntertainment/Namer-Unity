### Warnings (human decision requested)

**W1 [MINOR — needs decision]: The geometry bake and high-res occluder influence ONLY the interactive preview, never the generated asset.**
`NamerProcessor.Process` (NamerProcessor.cs:86-100) — invoked by the window's "Process with NAMER" button and the menu command — creates a fresh `NamerComputePipeline` (fresh, empty bake cache) and never sets `inspection.BakeSourceMesh`/`OccluderMesh` (only NamerEditorWindow sets them, NamerEditorWindow.cs:189/249/265; SourceInspector does not). Consequence: a user who primes a bake and/or assigns a high-res occluder sees baked AO in the preview, but the written NAMER material always uses image-space extraction AO (or the authored map). Preview and generated output diverge for the bake source. Note: no CONTEXT decision or plan specified bake wiring into the generation path — the executor implemented what was planned, so this is a planning-scope gap surfaced for a decision, not an executor failure. Later phases do not cover it (Phase 5 is painted/runtime-AO controls, not bake-to-generation).

**W2 [MINOR]: The first automatic bake runs synchronously on the UI thread.**
Plan 03's constraint text said the bake trigger "must never run inside the debounce's synchronous RecomputePreview path"; the implemented `RequestBake` is synchronous (03.1-02 deviation: `EditorApplication.delayCall` never fires in batchmode tests) and is invoked from `TriggerAutomaticBake` at the end of `RecomputePreview`, which itself runs from the debounced `Tick`. The invariant that matters — the bake never RE-runs per tick (cached + idempotent) — holds, but the first bake after selecting a mesh blocks the editor for its duration (up to 512² × 64 rays × BVH traversal). Perf feel needs a human check.

**I3 [INFO]: The green-channel user-blur kernel variant (`_BlurChannel = 1`) has no dedicated test.**
`CSBlurH/CSBlurV` are GPU-tested only through the extraction's red-channel low-pass. `NamerBlurSample`/`NamerBlurWrite` (NAMERAO.hlsl:41-49) select channels correctly by inspection, and `ApplyUserBlur` binds the right uniform, but a regression in the channel-select helpers would not be caught by the suite.

**I4 [INFO]: `BakeResultToTexture` runs a 512² C# marshal loop** (float AO → Color32). One-time transcode at the capped bake resolution; the actual bake math is Burst-compiled. Not per-pixel image processing on source textures; acceptable under the project constraint's intent.
