## Decisions Made
- The D-06 offset is additive and neutral-when-unset, applied in `InitializeNamerSurfaceData` after the shared decode (never inside `NAMER_DECODE_SURFACE`) so the macro signature and the Meta-pass call site are untouched.
- No `baseResidualPath` edit — the one-texture unbinding is already delivered by the existing D-13 drop; editing the `decomp == null` branch would regress non-decomposed Phase-3 assets that must still bind the Base PNG.
- The offset texture is a direct user-assigned `Texture2D` reference (no `AssetDatabase.LoadAssetAtPath`), surfaced as the shader's "Roughness Offset" inspector slot.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Declared `_RoughnessOffsetMap` in `NamerDebugView.shader`**
- **Found during:** Task 1 (D-06 shader input)
- **Issue:** `NamerDebugView.shader` `#include`s `NamerSurface.hlsl`, which now declares `TEXTURE2D(_RoughnessOffsetMap)`. - **Files modified:** `Packages/com.graffitientertainment.namer/Shaders/NamerDebugView.shader`
