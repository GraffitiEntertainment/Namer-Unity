Gap-closure decisions (reversible, no checkpoint — the debug sessions established the root causes and these are the minimal fixes):

- **Scene guard (3a):** graceful rejection, NOT scene support. Scene assets (.unity) are outside PRD selection scope (PRD: model, prefab, material, folder); scene-INSTANCE GameObjects already work via the empty-path branch and must not regress. Single choke point in `AddSubAssetMaterials` + a user-facing warning in `CollectMaterials` catch-all + a mirror guard in `ResolvePreviewMesh`.
- **Preview wiring (gap 2):** the correct fix is option 1 from the debug session — RecomputePreview must SUPPLY the 3A evaluate callback (composing it exactly like NamerProcessor) and attach `inspection.BakeSourceMesh`. Option 2 (consult the fit cache before early-out) alone is insufficient on first preview because the window's `_pipeline` fit cache is only populated by a fit run in that same pipeline instance. `RequestFit`/`HasCachedFit` stay untouched (the interactive off-debounce path is out of scope for this gap closure). `EvaluateRefitMaxError` is widened `private` → `internal` (1-word change) rather than duplicating ~25 lines into the window.
- **Vanish (3b):** the generated-mesh path is made safe via (a) bindposes-before-boneWeights reordering in `BuildSplitMesh`/`BuildPreviewSplitMesh` (Unity requires bindposes assigned before boneWeights on a skinned mesh — the current reversed order is the only static defect in the skinned path), and (b) a degenerate-bounds guard in `BindGeneratedMaterials` so a broken mesh is never bound. Live "does it render now" confirmation is a human-check (headless cannot render the Scene view).
</decisions>
