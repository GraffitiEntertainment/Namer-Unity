## Accomplishments
- Scene-asset (.unity) selections now degrade gracefully with a "scene asset" warning instead of throwing Unity's "Do not use ReadObjectThreaded on scene objects!" — from both SourceInspector and the preview-mesh resolver.
- The default FitDriven estimator now actually extracts roughness in the live preview: RecomputePreview attaches `BakeSourceMesh` and composes the same 3A evaluate callback NamerProcessor uses, so the Extracted Roughness debug channel and shaded preview consume the real extraction (previously black/scalar).
- Process no longer risks leaving a scene instance invisible: generated split meshes assign bindposes before boneWeights (skinned-safe), and a degenerate-bounds generated mesh is never bound (source mesh stays + warning).

## Decisions Made
- Scene guard is graceful rejection, not scene support — `.unity` assets are outside PRD selection scope and `LoadAllAssetsAtPath` cannot read scene objects; scene-instance GameObject selection (empty asset path) is unchanged and must not regress.
- Preview wiring takes option 1 from the debug session — RecomputePreview supplies the 3A evaluate callback (composed exactly like NamerProcessor) rather than relying on the fit cache, which is empty on first preview.
- `EvaluateRefitMaxError` is widened `private` -> `internal` (1-word change) instead of duplicating the ~25-line domain helper into the window.
