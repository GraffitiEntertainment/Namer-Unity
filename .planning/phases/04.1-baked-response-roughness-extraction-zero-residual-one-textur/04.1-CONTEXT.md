<domain>
## Phase Boundary

Assets whose base texture has material response (gloss/shading/cavity) baked in — and no dedicated roughness map (Neo is the motivating case) — get that baked response extracted into the **6-bit roughness bits (A 0–5)** of the packed surface texture. The cleaned base is then refit into vertex colors, the residual collapses, and the Phase-4 **D-13 auto-drop becomes the primary path**: *material = one RGBA8 surface PNG + a vertex-colored mesh* — no base texture bound, no residual file. The residual-texture fallback stays for assets whose base contains genuine albedo detail (decals, fabric weave, freckles) that survives extraction.

**Locked direction (from the exploration session — see canonical refs, not re-decided here):**
- **Format semantics do not change.** Bits 0–5 keep meaning "roughness"; only the *source* of the values changes. Golden-vector decode equivalence and `NamerSurface.hlsl` decode are untouched.
- Blur is the frequency separator: blurred base ≈ what vertex-color interpolation can hold; sharp-minus-blur remainder is the extraction candidate.
- Honest gate: "no residual texture" is earned per-asset by the fit (extract → refit → drop residual when within threshold, else fallback) — D-13 extended, never assumed.
- Neo is the acceptance case: processes to one texture, renders correctly, no residual file.
- **Anchored-inverted mapping (2026-09-16 revision):** the authored roughness scalar anchors the extracted map; Sobel magnitude (p90-scaled) pulls texels *down* toward gloss. See D-08–D-10 and the polarity note in canonical refs — this revises the original note's direct `edge-magnitude → roughness` polarity premise.

**Out of boundary:** metallic extraction from base (Blender has `extract_metallic`; not requested), stylization interplay incl. roughness simplification (Phase 5, STYL-06), bake-to-generation AO wiring (W1 accepted divergence stands), batch processing (v2 BATCH-01), packed-format versioning changes.

<decisions>
## Implementation Decisions

### Extraction gate
- **D-01:** Roughness extraction runs **automatically when the source has no authored roughness/smoothness map** — the 03.1 D-07 authored-wins pattern: an authored map always wins and its path stays byte-identical to today; extraction is the scalar-only/no-map path (Neo's case). Extraction never overrides authored data.
- **D-02:** The user gets a **strength override** control for the extraction — window control, EditorPrefs-persisted via `NamerProcessorSettings`, debounced live recompute (Phase-03 D-10 / Phase-4 D-15 pattern). Strength 0 = off.

### Estimator
- **D-03:** **Both estimator routes ship, as a selectable option:** Blender-parity Sobel (edge-magnitude on luminance, matching `namer_core.py` `extract_roughness`) **and** fit-driven (extraction strength calculated to minimize the post-refit residual — the adaptive-resolution-ladder philosophy). *Assumption to confirm at plan review: default = fit-driven* (the exploration notes' direction: "the Unity version should *calculate* how much to extract"); Sobel mode exists for Blender parity. **(Blender-parity clause SUPERSEDED 2026-09-16 — see D-09: both routes share the anchored-inverted mapping.)**
- **D-04:** The fit-driven pass follows the **`NamerAOBaker` pattern** (user-referenced): deterministic CPU Burst (`IJobParallelFor`, fixed tables, never `System.Random`), cancellable progress with injectable headless `shouldCancel`, an explicit one-time action **off the 300 ms debounce**, pipeline-level caching (`HasCachedBake`/`RequestBake` precedent), caller-owned result buffers. Per-pixel texture math stays GPU compute (NORM-03).

### Anchored-inverted extraction mapping (2026-09-16 revision — from the UAT round 4 /gsd-explore session)
- **D-08:** The extracted roughness map is **anchored at the authored scalar, Sobel dips toward gloss**, via the **dip-depth formula**: `roughness = saturate(_ScalarRoughness − _Strength · (mag / p90))`. The anchor invariant holds at every strength — quiet regions ≈ scalar regardless of the searched rung (Neo `_Smoothness: 0`: quiet packs ≈ 0.97 matte, edges dip toward ≈ 0.1 at strength 0.9), so the arbitrary normalization-dependent level failure (the UAT round 4 gloss bug) is structurally eliminated. The Sobel texture itself stays **direct-polarity** (`mag/p90` in `.r`) — the inversion happens in the remap consume sites only; no signal-inversion contract flip, debug view unchanged. Endpoint-lerp `lerp(scalar, 1 − mag/p90, strength)` was explicitly **rejected**: it discards the authored scalar at full adoption and re-levels glossy-authored sources matte. Known accepted limitation: edge texels clamp at 0 (mirror band) when `scalar < strength` on mid/glossy-authored sources — dip is not scaled to headroom; revisit only if a real asset shows it.
- **D-09:** The **Sobel estimator mode flips to the same anchored-inverted mapping** — one polarity across both routes; the estimator dropdown means *"who picks the strength"* (fit-searched vs manual slider), never *which polarity*. Supersedes D-03's Blender-parity clause. `namer_core.py extract_roughness` (direct `mag/np.max` polarity) is repositioned as **a testing idea, not ground truth** — the behavioral reference is how actual Blender (the product) treats an authored material; the packed decode already covers "specular" via `smoothness = 1 − roughness` (`NamerSurface.hlsl:73-74`). Documented as **parity deviation #2** (after #1: p90 vs np.max) in the UAT round-5 entry. The `NamerEditorWindow.cs` Sobel tooltip ("Blender-parity") must be rewritten.
- **D-10:** Fit-driven pack adoption **stays full-strength** (`isFitDriven ? 1f` — the existing `FitDriven_PackedRoughness_AdoptsSearchedStrengthNotSliderBlend` regression keeps pinning it). Under dip-depth, strength means *edge-dip depth only*, and `EvaluateRefitMaxError` (`NamerProcessor.cs`) fits vertex colors against the cleaned base without ever reading the roughness texture — the anchor costs the search no discriminating power, and quiet bases self-limit at ladder rung 0 (texture ≡ scalar ⇒ adoption is a no-op). A weak-fit re-gate/clamp was evaluated and **deliberately not built** (premise mostly false, heuristic constant + cache-key churn); it is the documented fallback **only if** UAT round 5 shows over-dipped extreme edges on a real asset.

### Fallback residual
- **D-05:** When the residual fallback triggers on an extraction-processed asset, the refit/residual is fit against the **cleaned (post-extraction) base** — extraction is never undone on the fallback path; the extracted roughness stays in bits 0–5.

### Escape hatch (roughness-offset input)
- **D-06:** The optional **single RGBA shader input to offset roughness ships in 04.1** — the fallback for per-texel detail that 6-bit extraction underfits. It is a material-level optional input, **not** a packed-format change: neutral-when-unset so decode equivalence and the one-texture happy path are untouched (unset input ⇒ byte-identical decode to today).

### Editor window ergonomics
- **D-07:** The processor window gets **collapsible sections (foldout dropdowns) plus scrolling** — the dialog has grown too tall to fit on screen. Controls group into functional sections; foldout state persists via the `NamerProcessorSettings` EditorPrefs pattern. *(Decided during plan-phase revision, 2026-09-06, alongside gray-area resolutions 1A/2A/3A/4A.)*
