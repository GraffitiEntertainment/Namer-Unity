## Fixed Issues

### CR-01: Default/identity path forces packed roughness to 1.0 (discards source smoothness)

**Files modified:** `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerComputePipeline.cs`
**Commit:** `c84f6df`
**Applied fix:** `BindAndDispatchSurfacePack` now receives `roughnessTex != null` (the produced-texture check) as its `hasExtractedRoughness` argument instead of `shouldExtract` (the intent flag). When the identity/legacy path runs (fit-driven but no refit objective, or a cancelled fit, or a nulled source mesh), no roughness texture is produced, so `_HasExtractedRoughness` is now `0` and the kernel leaves the scalar roughness untouched instead of lerping every texel toward the white fill at strength 1.0. The authored-map and `RoughnessExtractStrength == 0` paths are byte-identical to before (both flags were already false there).

### WR-01: `ReadBackGlobalMax` never disposes its `NativeArray<float>`

**Files modified:** `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerRoughnessPipeline.cs`
**Commit:** `7adfd41`
**Applied fix:** The `request.GetData<float>()` scan is now wrapped in a `try`/`finally` that disposes the `NativeArray<float>` on every path (including the successful return), matching the `AssetGenerator.ReadBackResidual` contract and eliminating the Sobel global-max readback leak.

### WR-02: Fit cache is keyed without the error threshold and caches failed fits

**Files modified:** `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerRoughnessPipeline.cs`, `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerComputePipeline.cs`
**Commit:** `edf3b40`
**Applied fix:** The fit cache key is now the 5-tuple `(meshId, estimator, w, h, maxErrorThreshold)`, so a strength fitted against one error threshold is never reused under a different one. Both `ExtractFitDriven` and `RequestFit` now cache only `Passed == true` results — a failed search (`Passed == false`) re-runs on the next request instead of reusing its honest-but-invalid max-ladder strength. `HasCachedFit` (and its `NamerComputePipeline` forwarder) gained a `maxErrorThreshold` parameter to stay consistent with the new key shape, and the cache declaration documents the threshold dependency. No output change for a single `Process` call (fresh pipeline, empty cache) — only the interactive cache-reuse path is corrected.
