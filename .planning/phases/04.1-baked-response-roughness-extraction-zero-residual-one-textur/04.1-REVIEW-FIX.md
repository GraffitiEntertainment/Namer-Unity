### CR-01: Live preview shows base × vertex-color double multiply for the one-texture outcome

**Files modified:** `Packages/com.graffitientertainment.namer/Editor/UI/NamerEditorWindow.cs`
**Commit:** c7ffda2
**Applied fix:** fixed: requires human verification (binding-logic change)

Adapted the review's suggested snippet into a three-way branch in `RecomputePreview`.
The review's literal two-way fix (bind `null` in the whole `else`) would have regressed
the decomposition-off Phase-3 preview: the saved material for that path binds the base
PNG at `_BaseResidualMap` (`AssetGenerator.Generate`:
`baseResidualPath = decomp != null ? residualWritePath : basePath`), so the preview must
keep binding `previewBaseMap` when `_decompOutput == null`. The new branch mirrors the
generator exactly:

- residual produced → bind `_decompOutput.Residual` (two-texture; unchanged),
- no decomposition ran → bind `previewBaseMap` (Phase-3 shape; unchanged behavior),
- decomposition ran, residual collapsed → bind `null` (one-texture parity with the saved
  material: albedo = `_BaseColor` × fitted vertex color, no base double-multiply).

The "before" pane is unaffected (it samples `inspection.Material`, not `_namerMaterial`),
so no separate material instance was needed.

### WR-01: Cancelling the fit silently writes un-extracted assets; cancelable progress bar during debounced preview recomputes

**Files modified:** `Packages/com.graffitientertainment.namer/Editor/Bake/NamerRoughnessFitter.cs`, `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerRoughnessPipeline.cs`, `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerComputePipeline.cs`, `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerProcessor.cs`, `Packages/com.graffitientertainment.namer/Editor/UI/NamerEditorWindow.cs`
**Commit:** 37a17f0 (fix) + 8a5555a (regression test)
**Applied fix:** fixed: requires human verification (cancel-state propagation)

Full propagation chain, per the review's direction:

1. `NamerRoughnessExtractResult` gains `bool Cancelled`; `ExtractFitDriven`'s cancelled
   branch returns it instead of an indistinguishable empty result.
2. `NamerComputeResult` gains `public bool RoughnessFitCancelled`; `Process` copies
   `fitDriven.Cancelled` onto the returned result.
3. `NamerProcessor.RunPipeline` emits
   `Debug.LogWarning("NAMER: roughness fit cancelled for material '<name>' — assets
   written WITHOUT roughness extraction.")` when the flag is set (write phase proceeds —
   the review offered warn-or-abort; the warning is the minimal non-destructive option).
4. `NamerEditorWindow.RecomputePreview` passes `() => false` as `shouldCancel` so the
   debounced preview recompute never pops an interactive cancelable progress bar on
   slider drags.
5. `NamerRoughnessFitter.Fit` tracks `bool interactive = shouldCancel == null` and only
   calls `EditorUtility.ClearProgressBar()` in that branch, so non-interactive callers
   (tests, batch, preview recomputes) no longer clear a host-owned progress bar.

**Test added:** `FitDriven_CancelledFit_SurfacesCancelledFlag` in
`Packages/com.graffitientertainment.namer/Tests/Editor/NamerRoughnessFitTests.cs`
(commit 8a5555a) — GPU-gated UnityTest mirroring the existing collapse-test fixture;
asserts `RoughnessFitCancelled == true`, `ExtractedRoughness == null`, and
`NormalizedBaseColorOwnedByRoughnessPool == false` when `shouldCancel` returns true.
Not executed (editor in use) — include in the orchestrator's regression run.

### WR-02: Fit cache key omits occlusion-map identity and base-map content — stale strength reuse

**Files modified:** `Packages/com.graffitientertainment.namer/Editor/Pipeline/NamerRoughnessPipeline.cs`
**Commit:** a1c8fcc
**Applied fix:** fixed: requires human verification (cache-key correctness)

`MakeFitKey` and the `_fitCache` key type gain `int occlusionMapId` (instance ID of
`inspection.OcclusionMap`, 0 when null — swapping `_OcclusionMap` now invalidates the
cached strength because AO feeds `CSNormalize`'s un-multiply of the Sobel input) and
`long baseMapStamp` from a new `AssetContentStamp(Texture2D)` helper — the imported
file's last-write UTC ticks, so re-importing/rebaking changed pixels into the SAME
`Texture2D` instance (stable instance ID) invalidates the entry. The stamp is 0 for
non-persistent textures (test fixtures), which the instance ID already distinguishes.
Key/comment blocks updated to document the invalidation contract. 12-element ValueTuple
keys remain valid C# 9 under Unity's Roslyn (verified: 0 CS1xxx from `csc
-langversion:9`).
