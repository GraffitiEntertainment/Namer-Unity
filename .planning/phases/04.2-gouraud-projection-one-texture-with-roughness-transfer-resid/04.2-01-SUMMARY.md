# Phase 04.2 Plan 01: Decomposition Engine — Projection Write-Back + Symmetric VcFloor + Residual Mode

**CSProjectBase projection write-back kernel + symmetric VcFloor in CSResidual make the residual quotient white by construction, with a NamerResidualMode gate override (AlwaysKeep/NeverKeep) and 5 new projection identity tests.**

## Accomplishments

- `CSProjectBase` kernel writes the rasterized Gouraud surface back as the cleaned base, preserving source alpha on covered texels and passing uncovered texels through unchanged — so `base/vcInterp` becomes an IEEE x/x identity (the 04.2 by-construction collapse).
- `CSResidual` now floors both operands symmetrically (`max(base,_VcFloor)/max(vc,_VcFloor)`), removing the measured 1.70% below-floor dark-texel exception class (RESEARCH Pattern 2).
- `NamerResidualMode { Gate, AlwaysKeep, NeverKeep }` added; `GenerateResidual` gains trailing optional `projectedOut` + `mode` parameters. Default path is byte-identical to 04.1 — no existing caller required modification.
- New `NamerProjectionTests` suite (5 GPU-gated tests) covers quotient-whiteness, dark/below-floor symmetric floor, source-alpha preservation + uncovered passthrough, and both residual modes. `ResidualPipelineTests` oracle flipped to the symmetric floor.

## Decisions Made

- Symmetric VcFloor adopted exactly as RESEARCH Pattern 2 recommends — no test pinned the legacy asymmetric dark-texel value except the ResidualPipelineTests oracle, which was flipped in the same change.
- `NamerResidualMode.Gate` kept as the default so plan 03 can wire the checkbox without a flag-day; `AlwaysKeep`/`NeverKeep` fall through / drop before any CSResidual dispatch.
- Projection write-back reused the existing `_VcInterp` rasterization (no new evaluator kernel) so dividend == divisor bit-for-bit — the anti-pattern of a divergent Gouraud evaluator was avoided.
