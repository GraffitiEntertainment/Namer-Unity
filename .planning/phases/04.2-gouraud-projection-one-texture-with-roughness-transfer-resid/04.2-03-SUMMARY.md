**Routed the projection (plan 01) and transfer (plan 02) through the production Process flow, deleted the retired 04.1 fit machinery, and landed the Dip Source / Write Residual / dip-depth UI — the product now behaves per the locked 04.2 design.**

## Accomplishments

- `NamerComputePipeline.Process` now takes a `NamerProjectionContext projection = null` instead of the retired evaluate/shouldCancel/maxErrorThreshold triplet. When a projection is supplied, the pipeline leases a projected base RT, invokes `context.Run(sourceBase, projectedOut)` after normalize, then branches: removed-detail transfer (RemovedDetail) → `ExtractTransferRoughness` with `roughnessDipApplied = true`; Sobel fallback (SobelEdge / no projection) → public `ExtractSobel` with `roughnessDipApplied = false`; authored metallic/gloss map → scalar unchanged. `NormalizedBaseColor` is the projected base, `SourceBaseColor` preserves the pre-projection source for the residual-ON dividend and the preview.
- `NamerProjectionContext` holds Split/Colors/Decomp plus the Run callback; `NamerComputeResult` gains `SourceBaseColor` and drops `RoughnessFitCancelled`/`NormalizedBaseColorOwnedByRoughnessPool`; release routing releases the two pool-owned normalized candidates in `ReleaseResult`.
- `NamerProcessor.CreateProjectionContext` builds the context whose Run does readback → `VertexColorFitter.Fit` → `ToColor32Array` → `GenerateResidual(..., projectedOut, AlwaysKeep/NeverKeep)`. The decomp block consumes `ctx.Split/ctx.Colors/ctx.Decomp` after `Process`; the legacy SobelEdge branch keeps its readback→fit→GenerateResidual flow with `mode` from `settings.WriteResidual`.
- Retired the 04.1 fit machinery wholesale: `NamerRoughnessFitter.cs` (+ `.meta`), the strength ladder, the fit cache, the frequency-separation kernels (`CSRoughnessBlurH/V/SharpDetail/SharpRemoval`), the old `CSRoughnessRemap`, `ExtractRoughness`/`ExtractFitDriven`/`RunFrequencySeparation`/`RunSharpRemoval`/`RequestFit`/`TryGetFitStrength`/`ClearFitCache`/`MakeFitKey`/`AssetContentStamp`, and the estimator enum.
- Renamed `NamerRoughnessEstimator` → `NamerDipSource { RemovedDetail = 0, SobelEdge = 1 }`; added `DipSource` ("NamerProcessor.DipSource") and `WriteResidual` ("NamerProcessor.WriteResidual") settings keys; default dip-depth moved 1f → 0.25f.
- Window: Dip Source popup, Roughness Dip Depth slider (reusing the strength key), Write Residual Texture checkbox, honest Sobel-fallback HelpBoxes, and Error Threshold / Residual Resolution de-emphasized when Write Residual is off. `RunDecompPreview` consumes the projection context (no second fit in the projection path).

## Decisions Made

- `NamerProjectionContext.Run` is the seam between the pipeline and the decomposition stage; the window calls `NamerProcessor.CreateProjectionContext` directly (same assembly), and the pipeline's `NormalizedBaseColor`/`SourceBaseColor` split preserves the source base only when a projection ran.
- `CreateProjectionContext` stays internal per the plan; the projection-era fit tests mirror its Run contract with a local helper (the tests assembly cannot see `internal` members).
- The retired-kernel names were dropped from the shader header comment so the verifier's strict "zero references to CSRoughnessRemap/CSRoughnessBlurH/CSRoughnessSharpRemoval" sweep stays clean.
