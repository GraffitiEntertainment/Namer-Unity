# Phase 04.2 Plan 06: GAP-1 Removed-Detail Soft-Clip Summary

**Soft-clip CSRoughnessTransferRemap's normalized depth to [-1,1] before the saturate dip so projection-error seam texels dip to saturate(scalar − strength) instead of gloss 0 — the default Removed Detail path loses its shiny edges and the dip-depth slider becomes monotonic.**

## Accomplishments
- Closed GAP-1 (04.2-HUMAN-UAT.md): the Removed Detail transfer's shiny edges and inert dip-depth slider. Root cause was the `CSRoughnessTransferRemap` remap computing `mag = removedLuma / p90` and then `saturate(scalar - strength * mag)` with no bound on `mag`; at projection-error texels (UV seams, triangle-boundary kinks, bright baked speckle) `|mag|` is 3–20x the p90 scale, so the `saturate` pinned those texels to roughness 0 at ANY slider value while `luma≈0` regions stayed at the scalar.
- Added the two-line soft-clip in `NAMERRoughness.compute`: `mag = clamp(mag, -1.0, 1.0);` between the p90 division and the saturate dip. Outliers now behave like the strongest legitimate removed detail — the roughness floor becomes `saturate(scalar - strength)`, so the slider modulates them monotonically.
- Corrected the misleading `NamerComputePipeline.cs` removed-detail comment: the removed-luma minuend is the SOURCE base (`baseColorOut`), the projected base is the subtrahend (the old "projected base is the dividend" wording was wrong).
- Added two capability-gated `[UnityTest]`s in `NamerRoughnessTransferTests.cs` pinning the behavior: `Transfer_SeamOutlier_SoftClipsAtUnitDepth` and `Transfer_SeamOutlier_DipIsMonotonicInStrength`.
