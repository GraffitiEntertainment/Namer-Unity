# Phase 04.2 Plan 07: Per-Pane Screen-Space Framing (GAP-2) Summary

**The side-by-side preview now frames EACH pane's own object with a 15px screen-space margin under the rotation-invariant bounding-sphere bound, and the pane centers track the orthographic size so both objects stay individually framed while zooming — closing the GAP-2 UAT verdict that the pair-centered framing left a large gap and pushed the mate object off-pane (UI-03/UI-04).**

## Accomplishments

- `NamerPreviewRenderer` reworked per the GAP-2 UAT verdict (which supersedes the locked 04.2-05 pair-plus-gap framing): the `HalfSeparation` / `PreviewGap` constants and the `_framedHalfWidth` / `_framedHalfHeight` fields are gone, replaced by `public const float MarginPx = 15f` and a single `private float _framedRadius` (the rotation-invariant `bounds.extents.magnitude`, degenerate fallback 1f).
- `OrthographicSizeForAspect` now takes `(float aspect, float rectHeightPx)` and fits the object into ONE pane (half the full rect) with the 15px margin on every edge: `horizFit = radius * rectHeightPx / max(paneWidthPx - 2*margin, 1)`, `vertFit = radius * rectHeightPx / max(rectHeightPx - 2*margin, 1)`, return `max(horizFit, vertFit) * zoomScale`.
- `Render` applies `OrthographicSizeForAspect(aspect, rect.height)` and derives `paneCenterWorld = orthoSize * aspect / 2f`, drawing the before/after meshes at `±paneCenterWorld` (minus the rotated bounds center) — the pane centers now track the orthographic size, so each object stays framed in its own pane while zooming. The shared yaw+pitch quaternion, light rotations, and `_preview.Render(true)` are byte-identical.
- `Frame` stores `_framedRadius`, resets `_zoomScale`/`_yaw`/`_pitch`, and keeps the neutral rotation — the bounding-sphere fit holds at ANY orbit, so no re-fit on orbit is needed. `Orbit`/`Zoom` are untouched (synced orbit/zoom invariant preserved).
- `NamerEditorWindow.cs` is not touched: `_preview.Render(_previewMesh, afterMesh, beforeMaterial, afterMaterial, previewRect)`, `_preview.Orbit(current.delta.x, current.delta.y)`, and `_preview.Zoom(current.delta.y)` call sites are byte-identical.

## Decisions Made

- The per-pane fit is computed from the rotation-invariant bounding sphere (`extents.magnitude`) at `Frame` time (neutral rotation). Because the sphere bounds the silhouette at ANY yaw/pitch, the fit holds under orbit — no re-fit on orbit is needed, and `Frame`'s existing neutral reset of yaw/pitch is kept.
- `MarginPx = 15f` — the middle of the user's "10-20 pixels around the edges" spec, pinned in tests so the checker can verify the exact framing math.
- The pane split stays entirely inside `NamerPreviewRenderer` (left half = before, right half = after). `NamerEditorWindow` is untouched, so GAP-2 shares no files with GAP-3 (which edits the window).

## Flip Audit (intentional framing-flip)

The GAP-2 UAT verdict supersedes the locked 04.2-05 "both objects wide plus PreviewGap" pair framing. The one changed test is `NamerPreviewRendererTests`' framing test (renamed) plus the render test's size assertion (signature-adjusted); no other test file changed.

| Pin | Old value (pair-plus-gap) | New value (per-pane, MarginPx 15) | Why |
|-----|---------------------------|------------------------------------|-----|
| tall mesh (1,2,0.5), aspect 2 | 2.3913 (radius + PreviewGap = 2.2913 + 0.1) | **2.4771** (radius × 400/370, square 400×400 px pane) | each pane frames its own object, not the pair |
| wide mesh (4,0.5,0.1), aspect 2 | 4.1324 (vertical pair bound) | **4.3593** (radius × 400/370) | per-pane fit dominates |
| wide mesh, aspect 1 | 4.8324 (HalfSeparation + radius + PreviewGap) | **9.4879** (radius × 400/170 — pane is half the full width, so the horizontal fit dominates) | the pane is 200×400 px, not the full 400×400 rect |

Rationale: the old framing computed ONE rotation-invariant pair-plus-gap size across the whole 2:1 rect and drew the meshes at a fixed world offset (±HalfSeparation = 0.7). Zooming in pushed the mate object out of its pane and the initial view left a large gap. The new fit frames each pane's object individually and re-derives the pane-center offset from the orthographic size.
