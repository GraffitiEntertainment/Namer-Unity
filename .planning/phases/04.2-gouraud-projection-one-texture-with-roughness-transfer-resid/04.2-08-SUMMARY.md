## Per-Warning Closure Evidence

### WR-01 — aspect-correct residual resample

- Added `ResolveAspectSize(longEdge, w, h, out outW, out outH)`: the `ResolutionLadder` value is now the residual's LONG edge; the short edge scales by `h/w` (or `w/h`) to preserve the source aspect. Every residual down-resample in `NamerDecompPipeline` (manual branch, adaptive search, `EvaluateResolution`, step-6 final resample, stats upsample) now routes through it or `longEdge`; no square `Resample(fullResidual, n, n)` remains.
- `Stats.ChosenResolution` reports the chosen LONG edge. For square sources (`w == h == longEdge`) this equals the width, so the existing `GenerateResidual_AdaptiveAndManualOverride` and `GenerateResidual_Gate_DistinguishesConstantVsGradient` square-source assertions passed unchanged.
- New test `ResidualPipelineTests.GenerateResidual_NonSquareBase_PreservesSourceAspect`: 256x128 base + manual index 5 (128px) → `ChosenResolution == 128`, `Residual.width == 128`, `Residual.height == 64`. **PASS** (was RED before the fix — the old width-only clamp produced a square 128x128).

### WR-02 — CR-03 CannotDecompose preview guard mirror

- `RunDecompPreview`'s projection branch now returns before consuming `ctx.Decomp` when `ctx.Decomp.Stats.CannotDecompose` is true, mirroring `NamerProcessor.cs:210-223`. `_decompStats` stays populated (honest 0% coverage), while `_decompOutput` and `_previewSplitMesh` stay null — so the CR-01 three-branch residual binding shows the non-decomposed Phase-3 shape Process actually writes. Grep gate (`ctx.Decomp.Stats.CannotDecompose`) green; full suite green.

### WR-03 — Decomp dispose before nulling

- `ReleaseDecompPreview` now runs `_projectionContext?.Decomp?.Dispose();` immediately before `_projectionContext = null;`. `NamerDecompOutput.Dispose` is idempotent (guarded by `_disposed`), so the happy path is safe and a thrown `Process` (post-`projection.Run`) no longer leaks the pool-leased residual RT across debounced recomputes. Grep gate (`_projectionContext?.Decomp?.Dispose()`) green.

### Metal shader warning — single-exit-point NAMER_DECOMP_HEATMAP

- `NAMERDecomp.hlsl` body replaced the early-return chain with four unconditionally-computed `lerp` segments selected by a single nested ternary (`return (x < 0.25) ? seg0 : (x < 0.5) ? seg1 : (x < 0.75) ? seg2 : seg3;`). The c0..c4 anchors and the four lerp coefficients (`x/0.25`, `(x-0.25)/0.25`, `(x-0.5)/0.25`, `(x-0.75)/0.25`) are byte-identical; boundary semantics are unchanged (x = 0.25 → seg1 at t = 0 → c1).
- Shader assets (`NAMERDecomp.hlsl`, `NAMERDecomp.compute`, `NamerDebugView.shader`) were force-reimported in the live editor. The post-reimport Editor.log tail and the entire EditMode suite run (which dispatches `CSErrorHeatmap` repeatedly) both contained **zero** occurrences of `potentially uninitialized variable (NAMER_DECOMP_HEATMAP)` — the false-positive Metal warning is gone.
