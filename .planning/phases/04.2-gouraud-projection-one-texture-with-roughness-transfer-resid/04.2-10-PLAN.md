Close GAP-5 (04.2-HUMAN-UAT.md, round 3) — the rotation center drifts during orbit.

**This plan amends 04.2-09's orbit-time anchor recompute.** The framing lineage, each step
user-directed by UAT verdict:
`04.2-05 pair-plus-gap -> 04.2-07 per-pane-centered -> 04.2-09 divider-anchored recompute ->

Round-3 defect (code-verified): `NamerPreviewRenderer.Render` recomputes the pane anchor
every frame from the CURRENT rotated horizontal half-extent (`PaneAnchorWorld` ->
`HorizontalHalfExtentWorld`, NamerPreviewRenderer.cs:233-237), so as the silhouette width
changes under yaw/pitch the object's rotation center translates — the model slides while
the user orbits instead of spinning in place about its first positioning. The per-Render
recompute was plan 09's way of keeping the inner edge at exactly 10 px at every orbit; the
user's round-3 verdict is that the FIRST positioning must be stable under rotation.

Design decision (planner's call, grounded in code + the user's two-windows spec): **option
(a) — per-pane clipping** via a rotation-stable anchor plus TWO preview cycles (one mesh per
render target).
- The anchor becomes rotation-stable: `PaneAnchorWorld` uses the neutral `_framedHalfWidth`
  (captured at Frame) instead of `HorizontalHalfExtentWorld`. The center is therefore the
  first positioning, and zoom still grows each model outward (the anchor keeps its
  `InnerMarginPx * 2*orthoSize/rectHeightPx` term). `HorizontalHalfExtentWorld` retires.
- The extreme-rotation overflow is clipped by rendering each pane's mesh into its OWN render
  target, then drawing only the pane-relevant half of each target in the window: `Render`
  performs two `BeginPreview → DrawMesh(one mesh) → Render(true) → EndPreview → Graphics.Blit`
  cycles (the before mesh at −anchor in cycle 1, the after mesh at +anchor in cycle 2); each
  cycle blits its utility RT into a per-pane persistent RenderTexture owned by the renderer
  before the next cycle begins, and returns a `PreviewRenderResult { Before, After }`
  referencing those persistent RTs. The window draws the before RT's left half
  (texcoords 0,0,0.5,1) into the left half-rect and the after RT's right half (0.5,0,0.5,1)
  into the right half-rect. Each RT contains only its own mesh, so the far half of each RT is
  empty background — discarding it clips any overflow past the divider (world x=0) invisible:
  genuine per-pane windows, matching the 1 px outline plan 09 added.

Why two preview cycles (and why the single-texture display-time crop was withdrawn):
- The original round-3 drafting proposed a display-time half-texcoord crop of the SINGLE
  combined texture. That is a visual no-op. The divider (world x=0) already maps to the exact
  center of the combined texture, so drawing the left half (0,0,0.5,1) into the left half-rect
  and the right half (0.5,0,0.5,1) into the right half-rect reproduces the same screen mapping
  as the current single full-rect draw (u = 0.5·(p.x−x)/(w/2) = (p.x−x)/w). A before-mesh
  pixel that crossed the divider lands in the RIGHT half of the combined texture and is drawn
  by the right pane's half-draw — cross-pane overlap remains visible. The "clipped invisible"
  claim was false: what was pinned (option a) was not what was delivered (option c
  encroachment).
- `camera.rect`/scissor two-pass inside one BeginPreview requires a
  `CameraClearFlags.SolidColor -> Nothing` clear-flags dance between passes — order-sensitive
  GL state, the exact fragility plan 09's outline decision explicitly avoided ("baking it into
  the RT ... fragile/hard to verify headlessly").
- Option (c) (accept encroachment) is dishonest for this asset class: on a near-cubic mesh
  like Neo the rotated X half-extent reaches |cos·yaw|·ex + |sin·yaw|·(|sin·pitch|+|cos·pitch|)·ey,
  i.e. ~1.4x the neutral extent at yaw 45/pitch 0 and 1.414 at yaw 90/pitch 45 — overlap would
  appear in ORDINARY orbit, resurrecting the round-2 overlap complaint under rotation instead
  of zoom. The plan therefore chooses real clipping.
- Two preview cycles deliver option (a) honestly. Texcoord math for THIS design (derived):
  each cycle renders with the full-rect-aspect camera; the before mesh sits at world x<0 so
  its content lives in the LEFT half of its RT (world x=0 → RT center), and the after mesh at
  x>0 lives in the RIGHT half of its RT. Drawing the before RT's left half into the left
  half-rect (and the after RT's right half into the right half-rect) is a 1:1 mapping because
  each RT is exactly previewRect-sized — the pane content keeps its native preview scale while
  the far half of each RT (where overflow would land) is discarded. Both cycles share one
  orthographic camera transform, one orthographic size, one light setup, and one meshRotation,
  so D-09's shared-rotation/silhouette invariant holds; the cost is two camera renders + two
  Graphics.Blit copies per Repaint instead of one render (editor-only, debounced — acceptable;
  the blits are full-frame GPU copies at preview size, negligible). The horizontal split spans full
  Y, so the IMGUI texture Y-flip gotcha does not apply.

Purpose: the preview is the acceptance instrument for the transferred-roughness LOOK
(UI-03/UI-04) — the A/B judgment must show two models that hug the divider and each spin
in place about a fixed center, with any extreme-rotation overflow hidden by the pane
window edge rather than translating the model.

Output: rotation-stable anchor in NamerPreviewRenderer.cs (HorizontalHalfExtentWorld

       ```
       private Texture RenderPane(Mesh mesh, Material material, Rect rect, float orthoSize,
                                  Quaternion meshRotation, Vector3 rotatedBoundsCenter, float drawOffsetX,
                                  ref RenderTexture paneTexture)
       {
           _preview.BeginPreview(rect, GUIStyle.none);
           ApplyCamera();
           _preview.camera.orthographicSize = orthoSize;
           _preview.lights[0].transform.rotation = Quaternion.Euler(50f, -30f, 0f);
           _preview.lights[1].transform.rotation = Quaternion.Euler(340f, 218f, 177f);
           Vector3 position = new Vector3(drawOffsetX, 0f, 0f) - rotatedBoundsCenter;
           _preview.DrawMesh(mesh, position, meshRotation, material, 0);
           _preview.Render(true);   // allowScriptableRenderPipeline=true is REQUIRED for URP materials
           Texture utilityRt = _preview.EndPreview();   // the utility's CACHED RT — reused by the next BeginPreview
           return BlitToPane(ref paneTexture, utilityRt);  // copy NOW, before the next cycle overwrites it
       }

       private RenderTexture BlitToPane(ref RenderTexture pane, Texture source)
       {
           int w = source.width;
           int h = source.height;
           if (pane == null || pane.width != w || pane.height != h)
           {
               if (pane != null)
               {
                   pane.Release();
               }

               pane = new RenderTexture(w, h, 0, source.graphicsFormat)
               {
                   name = "NamerPreviewPane",
                   hideFlags = HideFlags.HideAndDontSave,
               };
           }

           Graphics.Blit(source, pane);
           RenderTexture.active = null;   // restore EndPreview's post-condition — Render runs mid-OnGUI (C-3)
           return pane;
       }
       ```
       The per-cycle order BeginPreview → ApplyCamera → orthoSize → lights → DrawMesh →

       PreviewRenderUtility reuses its internal cached RT on the next BeginPreview at an

       blit MUST also restore `RenderTexture.active = null` immediately after
