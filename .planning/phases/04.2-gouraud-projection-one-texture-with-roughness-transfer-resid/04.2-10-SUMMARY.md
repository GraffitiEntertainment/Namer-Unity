# Phase 04.2 Plan 10: Fixed-Center Orbit + Per-Pane Clipping (GAP-5) Summary

**The preview's orbit center is now the first positioning — `PaneAnchorWorld` uses the neutral `_framedHalfWidth` captured at Frame instead of the per-Render rotated horizontal half-extent (which was visibly translating the model during orbit) — and `Render` now runs two BeginPreview→DrawMesh→Render(true)→EndPreview cycles, each blitting its utility RT into its own persistent per-pane RT, so the window draws the before RT's left half and the after RT's right half and extreme-rotation overflow past the divider is clipped invisible (UI-03/UI-04).**

## Accomplishments

- `HorizontalHalfExtentWorld()` is retired (zero matches under `Packages/`); `PaneAnchorWorld(aspect, rectHeightPx)` now returns `_framedHalfWidth + InnerMarginPx * (2f * orthoSize / max(rectHeightPx, 1f))` — the neutral X half-extent captured at Frame plus the zoom-scaled inner margin. The anchor is therefore FIXED under orbit (the first positioning) while zoom still grows each model outward from the divider. The class/PaneAnchorWorld/GetPaneDrawOffsets doc comments and the Render inline comment were rewritten to drop the stale "rotated horizontal half-extent" rotation-dependence sentences (W-1).
- `Render` now returns a `PreviewRenderResult` struct (Before/After/IsValid) added above the class. The 6-arg body runs two `RenderPane` cycles (before at `−anchor`, after at `+anchor`), each of which re-establishes its own full setup (BeginPreview → ApplyCamera → orthoSize → light rotations → DrawMesh(one mesh) → `Render(true)` → EndPreview) and immediately `Graphics.Blit`s the utility's cached RT into its own persistent pane RT (`_beforePaneTexture`/`_afterPaneTexture`) before the next cycle overwrites it (C-2). `BlitToPane` matches `source.graphicsFormat`, reallocs on rect-size change, and restores `RenderTexture.active = null` after the blit (C-3). `Cleanup()` releases both pane RTs after the existing `_preview.Cleanup()` block.
- `NamerEditorWindow.DrawPreviewSection` now calls `DrawPreviewPaneTexture(previewRect, previewResult)` in the `previewResult.IsValid` branch: `GUI.DrawTextureWithTexCoords` draws the before RT's left half into the left half-rect and the after RT's right half into the right half-rect. Each RT contains only its own mesh, so the far half of each RT is empty background — discarding it clips any overflow past the divider invisible (genuine per-pane windows, option a). `ScaleMode.StretchToFill` is gone; the 1 px outline still draws on top.
- The full EditMode suite is green in the live editor at `TOTAL passed=151 failed=0 skipped=0` (expected 152 → 151 drift: one test deleted, none added). All 7 `NamerPreviewRendererTests` pass, including the renamed `PaneAnchor_FixedCenter_InnerEdgePinnedAtNeutral_AcrossZoom`, the flipped `GetPaneDrawOffsets_MirrorsDividerAnchor`, and the in-place-updated `Render_OrthoCamera_OneSharedRotation_SizeMatchesFit`.

## Decisions Made

- Per-pane clipping (option a) via two preview cycles, not the withdrawn single-texture half-texcoord crop (which the checker proved a visual no-op) and not `camera.rect`/scissor (the order-sensitive GL clear-flags fragility plan 09 explicitly avoided).
- The anchor's rotation-stability is pinned at `1e-6f` after `Orbit(35, 20)` in two tests — the round-3 recompute moved the anchor ~0.57 world there, so the flipped assertion is discriminating against any re-introduced rotated-extent recompute.
- `BlitToPane` must copy the utility RT into the persistent pane RT immediately after `EndPreview` (before the next `BeginPreview` reuses the cached utility RT) and restore `RenderTexture.active = null` right after the blit (Render runs mid-OnGUI).
