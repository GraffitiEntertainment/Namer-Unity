# Phase 04.3: Adaptive residual resolution via percentile coverage - Pattern Map

**Mapped:** 2026-09-22
**Files analyzed:** 8 (all modifications to existing files; zero new files)
**Analogs found:** 8 / 8

> **Headline finding for the planner:** the within-tolerance fraction D-03 calls a "new
> reduction statistic" **already exists end-to-end**. `CSErrorHeatmap` writes the per-texel
> `err <= _Threshold` flag into `_CoverageStat` (`NAMERDecomp.compute:342,346`), `CSReduce`
> averages it (`.r` channel), and `BuildStats` already normalizes it into
> `NamerDecompErrorStats.Coverage` (`NamerDecompPipeline.cs:640-642`). What is missing is
> only that `EvaluateResolution` reduces **only** `errorStat` and never consumes
> `coverageStat` (`NamerDecompPipeline.cs:525-526`). The compute shader most likely needs
> **zero changes**; the gate work is C#-side.
>
> Note: CONTEXT D-03 characterizes the existing `Coverage` stat as "fraction of texels
> needing residual" — the code disagrees. Code + UI say: *fraction of UV-covered texels
> reconstructed within the error threshold* (`NamerDecompPipeline.cs:33-36`,
> `NamerEditorWindow.cs:1749-1750`). That IS the percentile statistic. Planner must pick a
> distinct name for the new achieved-coverage-at-chosen-rung field (D-07) to avoid
> conflation with the existing `Coverage`.

### 1. `NamerDecompPipeline.cs` — the percentile gate (D-01, D-02)

**Analog:** the file's own max-error gate + the `BuildStats` coverage normalization.

**D-01 replacement target — the strict gate** (lines 482-501; the break at 492-496 is what

```csharp
// NamerDecompPipeline.cs:482-501 (ChooseResolution, adaptive D-16 walk)
int longEdge = Mathf.Max(w, h);
int chosen = longEdge;
for (int i = 0; i < ResolutionLadder.Length; i++)
{
    int r = ResolutionLadder[i];
    if (r >= longEdge)

}
```

**The statistic the gate needs — already computed.** `RunErrorHeatmap` (dispatched per rung
at line 524) writes BOTH stat textures; `EvaluateResolution` reduces only one (lines
522-527):

```csharp

{

    ReduceStats stats = ReduceToStats(errorStat, w, h, avgA, avgB);
```

The gate change: also `ReduceToStats(coverageStat, w, h, avgA, avgB)` and compute the
covered-normalized within-tolerance fraction using the exact `BuildStats` math (lines
638-645):

```csharp
// NamerDecompPipeline.cs:638-645 (BuildStats — the normalization pattern to copy)
float fractionCovered = error.CoverageFraction;
float avgError = fractionCovered > 0f ? error.MeanErr / fractionCovered : 0f;
float coveragePct = fractionCovered > 0f ? coverage.MeanErr / fractionCovered : 0f;
```

Why the normalization is mandatory: uncovered texels write `0` into `_CoverageStat.r`
(compute line 335) and `1.0` into `_ErrorStat.b` only for covered texels (line 345), so the
raw reduce yields within-count / ALL texels; dividing by `error.CoverageFraction` yields
within-count / COVERED texels — the D-01 "fraction of texels" must be over covered texels
to match the existing `Coverage` semantics.

### 2. `NAMERDecomp.compute` — likely zero-change (D-03)

**Analog:** itself. The per-texel within-threshold flag and its reduction already exist.

```hlsl
// NAMERDecomp.compute:339-346 (CSErrorHeatmap — the statistic D-03 describes)
float3 b = _BaseLinear[id.xy].rgb;
float3 rec = (_FitOnly > 0.5) ? vc.rgb : (vc.rgb * _ResidualOut[id.xy].rgb);
float err = (abs(rec.r - b.r) + abs(rec.g - b.g) + abs(rec.b - b.b)) / 3.0;
float within = (err <= _Threshold) ? 1.0 : 0.0;

_ErrorHeatmap[id.xy] = float4(NAMER_DECOMP_HEATMAP(err / max(_MaxObservedErr, 1e-6)), 1.0);
_ErrorStat[id.xy] = float4(err, err, 1.0, baseA);
_CoverageStat[id.xy] = float4(within, 0.0, 0.0, 1.0);
```

Uncovered branch writes zeros so they never count (lines 331-336). `CSReduce` averages `.r`
per 8x8 block (lines 362-389), ping-ponged by `ReduceToStats` (`NamerDecompPipeline.cs:555-581`)
and read back float-exact via `RGBAFloat` readback (lines 583-636 — keep this; do NOT
introduce an RGBA32 readback for the new stat, see the WR-01 comment at 586-593).

Only if the planner chooses a different coverage denominator would a kernel change be
needed — flag it, but the default path needs none.

## Shared Patterns

### Slider write-back + debounce (applies to the new coverage slider)
**Source:** `NamerEditorWindow.cs:1670-1683` — excerpt above. Every control: local
`new*` value, `Mathf.Approximately`/`!=` compare, assign field, assign `_settings.*`,
`_afterPanelState.MarkTweaking()`, `MarkDirty()`. Never write to disk from the slider.

### GPU stat reduction contract (applies to any new statistic)
**Source:** `NamerDecompPipeline.cs:555-636` + `NAMERDecomp.compute:354-390`.
Stat channels live in fixed RT slots (`.r` mean / `.g` max / `.b` mean-flag / `.a` min);
`ReduceToStats` ping-pongs `avgA`/`avgB`; readback is `TextureFormat.RGBAFloat` with
`forcePlayerLoopUpdate = true` + `WaitForCompletion` (edit-mode async pump, WR-01 float
precision). A new reduction statistic reuses these channels — no new RTs, no new kernel.

### Honest-stats fallback (applies to D-08)
**Source:** `NamerDecompPipeline.cs:482-484` (`chosen = longEdge` initial value = the
fallback) + zeroed stats objects at 224-233/316-325. When no rung passes, the walk already
falls back to the source long edge without a warning — keep that shape; populate the new
achieved-coverage field honestly on the fallback too.

### Doxygen + naming conventions (applies to all files)
Every public/internal member carries a `<summary>` citing the decision ID (e.g. "(D-15;
default 0.02)"). Private constants `k`-prefixed camelCase (`kMaxObservedErrFloor`,
`NamerDecompPipeline.cs:115-117`); defaults live in `NamerEditorConstants` as
`Default*` consts, never inline in the UI.
