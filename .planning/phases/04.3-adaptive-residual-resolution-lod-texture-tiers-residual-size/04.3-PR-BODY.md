## Summary

**Phase 04.3: Adaptive residual resolution via percentile coverage**
**Goal:** Replace the max-error gate in the residual-resolution search with a percentile coverage gate — pick the lowest rung of the existing {2048..128} down/up round-trip ladder where ~99% of texels stay within the color-recreation tolerance (often 512×512).
**Status:** Verified ✓

The residual-resolution ladder in `NamerDecompPipeline.ChooseResolution` now accepts a coverage target instead of breaking on a single worst-case texel: a rung passes when ≥ target (default 99%) of UV-covered texels reconstruct within the error tolerance, so typical assets land at 512×512 instead of over-conservatively large residual textures. The target is persisted via EditorPrefs (`NamerProcessorSettings.CoverageTarget`), plumbed through `NamerProjectionContext`/`CreateProjectionContext` into `GenerateResidual` (projection + legacy Sobel branches), and exposed in the NAMER Processor window as a Coverage Target slider (0.90–1.00, 0.005 quantization, default 0.99) beside the Error Threshold slider (max extended 0.10 → 0.25). The stats Residual row reports achieved coverage honestly ("written @512px, coverage 99.4%") with a long-edge-fallback tooltip when no rung passes. Deferred by decision: LOD-based texture tiers — zero LOD code added (pending the Ultimate LOD System decision).
