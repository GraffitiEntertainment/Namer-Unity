# Phase 5 — UI Design Contract (Unity IMGUI)

> Visual and interaction contract for the Stylization phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This project is a Unity editor plugin, not a web frontend. Web-template dimensions (spacing, typography, color) are translated into Unity IMGUI terms below. The design language is the EXISTING `NamerEditorWindow` idiom set — this phase extends it, it does not invent a new one.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Unity Editor IMGUI — shadcn gate not applicable; not a React/Next.js/Vite stack) |
| Preset | not applicable |
| Component library | `UnityEditor` built-ins: `EditorGUILayout` (Foldout, Slider, Toggle, ToggleLeft, Popup, ObjectField, LabelField, HelpBox), `EditorGUI.BeginDisabledGroup`/`DisabledScope`, `EditorStyles` |
| Icon library | none — the house UI is text-only (miniButton "+"/"–" labels; no iconography anywhere in `NamerEditorWindow`) |
| Font | Unity Editor skin default (no custom fonts; light/dark themes follow the Editor automatically) |

**Baseline (binding):** `Packages/com.graffitientertainment.namer/Editor/UI/NamerEditorWindow.cs`
- Section idiom: `EditorGUILayout.Foldout(_settings.FoldoutX, "Name", true)` + early return (`:944`, `:1473`, `:1545`, `:1614`, `:1805`)
- Slider idiom: `EditorGUILayout.Slider(new GUIContent(label, tooltip), v, min, max)` → write-through to persisted setting → `MarkTweaking()` → `MarkDirty()` (`:1500-1517`)
- Gate-row idiom: `EditorGUILayout.ToggleLeft(new GUIContent(label, tooltip), v)` in a horizontal row under a `boldLabel` + `miniLabel` header pair (`DrawStepSwitches`, `:873-940`)
- Popup idiom: `EditorGUILayout.Popup(new GUIContent(label, tooltip), index, new[]{ "Option A", "Option B" })` (`:1481`, `:1709`)
- Stats idiom: `boldLabel` "Statistics" + tooltip'd `LabelField(label, value)` rows; "—" placeholder before data exists (`DrawDecompStats`, `:1758-1800`)
- Empty-state idiom: `EditorStyles.largeLabel` heading + `EditorStyles.label` body-with-next-step + `Space()` (`:950-957`)
- Status idiom: miniLabel "Recomputing preview…" / "Preview up to date" (`:1744-1746`); HelpBox `MessageType` for warnings/errors (`:982`, `:1640`, `:1859`)
- Busy idiom: `EditorGUI.BeginDisabledGroup(inspection == null || _busy)` wrapping each section's controls
- CTA idiom: `GUILayout.Button` with busy label swap "Process with NAMER" → "Processing…" (`:1849-1853`)
- Debounce: `NamerEditorConstants.DebounceSeconds = 0.3f` — the named constant, never an inline number

**Focal point:** the reference-list header + `Extract Style Stats` button on the profile inspector; the Before/After preview pane on the Processor window. (Checker rec — Visuals dimension.)

## Spacing Scale (IMGUI translation)

IMGUI auto-layout owns vertical rhythm; the contract constrains the exceptions we control. All declared values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| Row spacing | platform default (`EditorGUIUtility.standardVerticalSpacing`, 2px) | All control rows — never padded manually |
| Group gap | one `EditorGUILayout.Space()` | Between logical groups inside a section (header block / list / sliders / advanced); after the last row of each section — exactly as existing sections do (`:986`, `:1748`) |
| Thumbnail | 64×64 px | Reference-image slot preview, left of each ObjectField (matches material albedo-slot preview scale) |
| List footer buttons | `miniButtonLeft`/`miniButtonRight` pair, default heights | "+ / –" row under the reference list |
| Foldout indent | one `EditorGUI.indentLevel++` (platform 15px — Unity-owned, declared exception) | Nested explanation HelpBoxes (`:1524`) and Advanced sub-controls |

Exceptions: none beyond the Unity-owned 15px indent level (platform constant, not ours).

## Typography (EditorStyles roles)

No custom fonts, sizes, or weights. Exactly 4 roles, mapped to EditorStyles (2 visual weights: regular + bold). Light/dark variants follow the Editor skin. Body line-height is EditorSkin-owned (platform default) and non-authorable, mirroring the Spacing section's delegation of Unity-owned defaults. (Checker rec — Typography dimension.)

| Role | Style | Usage in this phase |
|------|-------|---------------------|
| Section/heading | `EditorStyles.boldLabel` | "Stylization" foldout title; profile "Reference Images (3–10)"; "Advanced"; "Statistics" |
| Help/status line | `EditorStyles.miniLabel` | Header explainer lines, count honesty line, "Recomputing preview…", popup-disabled hints |
| Empty-state heading / pane caption | `EditorStyles.largeLabel` | "No reference images." heading; "Before"/"After" pane captions (unchanged, `:1007-1008`) |
| Body/labels/values | `EditorStyles.label` (+ `popup` for popups) | Slider labels, stat rows, empty-state body copy, ObjectField labels |

Tooltips live in `GUIContent.tooltip` only (hover), never duplicated in-panel — house rule.

## Color (Unity Editor skin — zero custom colors)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Editor window default background | Everything |
| Secondary (30%) | Standard control chrome (foldout arrows, sliders, text fields, boxes) | Everything |
| Accent (10%) | NONE custom — this phase introduces zero hex values | reserved for: nothing (no colored buttons, no custom tinting; Unity skin supplies the default button/accent) |
| Destructive | none (no destructive-colored actions exist in this phase — see Copywriting) | — |

Semantic color = `MessageType` mapping only: `Warning` (staleness, guard fallbacks), `Error` (failures), `Info` (fallback explanations). The stylized preview mode must NOT be distinguished by color — the "After" pane caption/model swap carries it (skin parity required).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — window | "Process with NAMER" (unchanged; busy: "Processing…") |
| Primary CTA — profile | **"Extract Style Stats"** (busy: "Extracting…") |
| Empty state heading (profile refs) | "No reference images." |
| Empty state body (profile refs) | "Add 3–10 reference images with the + button, assign textures, then Extract Style Stats." |
| Empty state (window, no profile) | After View popup rendered disabled + miniLabel: "Attach a Style Profile to enable the stylized view." |
| Not-extracted state | Statistics rows show "—"; attach-state miniLabel reads: `<profileName> — not extracted` vs `<profileName> — palette extracted (N anchors, M references)` |
| Error state (extraction) | HelpBox Error: "Extraction failed: {texture} could not be read. Check the texture's Read/Write import setting." |
| Error state (unexpected) | HelpBox Error: "Extraction failed: {exception message}" — problem + retry path, mirroring "Processing failed: …" (`:1894`) |
| Staleness warning | HelpBox Warning: "Reference images changed since extraction — Extract Style Stats again to update the palette." |
| Destructive confirmation | None required. "–" removes the last slot and re-Extract overwrites stored stats — both are undoable (`Undo.RecordObject`) or deterministically recomputable; nothing touches source or generated assets. No confirmation dialogs (house has none, including for Process itself). |

**Tooltip suffix sentences (verbatim, house law):**
- Debounced controls append: `"Recomputes the preview in memory " + NamerEditorConstants.DebounceSeconds + " s after the slider stops — nothing is written to disk."`
- A control that responds instantly (none new this phase — the existing live-uniform channel stays window-side) would instead carry the live phrasing: "…gate the shader only (live, no re-Process needed)." (`:876`)

## Component Inventory (Phase 5)

### A. Processor window — new "Stylization" foldout (`NamerEditorWindow`)

Placed between the "AO" and "Decomposition" foldouts (draw order mirrors pipeline order: normalize → roughness → AO → **stylize** → decompose/fit, per D-01).

| # | Control | Type | Behavior |
|---|---------|------|----------|
| W1 | Foldout "Stylization" | `EditorGUILayout.Foldout` | `FoldoutStylization` pref, default false (house default for non-Source foldouts) |
| W2 | "Style Profile" | `EditorGUILayout.ObjectField(typeof(NamerStyleProfile), allowSceneObjects: false)` | Attach/select/detach → debounced 0.3 s recompute (D-06: applies to preview on load/change); persistence = EditorPrefs string key holding the profile asset GUID (EditorPrefs cannot store object refs — GUID string mirrors the `NamerProcessorSettings` shape) |
| W3 | Attach-state line | `miniLabel` | "not extracted" / "palette extracted (N anchors, M references)" — honesty for what the preview is using |
| W4 | "After View" popup | `EditorGUILayout.Popup`, options `{ "NAMER", "Stylized NAMER" }`, default 0 | Lives in Preview/Debug above the Before/After caption row; flip → debounced recompute (decomposition-toggle flip precedent, `:349`); disabled with hint when no profile attached (UI-04) |

No new Stage & Shader Gates toggle — the profile reference itself is the opt-in gate (null = stylization stage off), matching the opt-in `DecompositionEnabled` precedent. Profile sliders at 0 are identity ("0 = off" house semantics, `NamerEditorConstants.DefaultRoughnessExtractStrength` comment).

### C. Persistence & constants

- `NamerProcessorSettings` (EditorPrefs) additions: `FoldoutStylization` (bool, key `NamerProcessor.FoldoutStylization`, default false), `AfterView` (int, default 0), `StyleProfileGuid` (string) — key naming follows the existing `NamerProcessor.*` pattern (`NamerProcessorSettings.cs:34-39`).
- `NamerEditorConstants` additions (named constants, no magic numbers): `MinReferences = 3`, `MaxReferences = 10`, `DefaultStyleStrength = 0.5f`, `DefaultSmoothingStrength = 0f`, `DefaultCavityFloor = 0f`, `DefaultNormalDetailReduction = 0f`, `DefaultRoughnessSimplify = 0f`, `DefaultReferenceWeight = 1f`, `DefaultHueMode = 0`.
- Profile-side values (refs, weights, sliders, stats, fingerprint) serialize on the `NamerStyleProfile` asset — NOT EditorPrefs (D-06: the profile IS the persisted truth; saved packed output must equal the preview).

## Interaction Contract

| Interaction | Response | Rule |
|-------------|----------|------|
| Profile attach / detach / swap (W2) | Debounced 0.3 s re-Process of preview | Applies on load AND on change (D-06) |
| After View flip (W4) | Debounced recompute; pane swap only | Preview-only — never writes disk |
| ANY profile slider (P7–P11, P13, P14) | Debounced 0.3 s recompute + `Undo.RecordObject`/`SetDirty` write to asset | Live-uniform instant path NOT used for new controls — all Phase 5 controls are compute/bake stages (D-06/D-07); the existing window AO-strength instant channel is unchanged |
| "+ / –" (P3) | Immediate asset edit; NO recompute | Extraction is the only path that reads references (D-04) |
| Extract Style Stats (P5) | Synchronous, cancellable progress bar; button disabled while running (label "Extracting…") | Runs once per explicit click; deterministic CPU Burst; never on debounce |
| Process with NAMER | Bakes with the attached profile's persisted values | Saved packed output == preview (phase boundary invariant) |
| Busy/disable states | `BeginDisabledGroup` under `_busy`/extraction; "+" disabled at 10; "–" disabled at 0; Extract disabled < 3 assigned refs; After View disabled without profile | Every disabled state carries a visible reason (P4 line / miniLabel hint / HelpBox) — no silent dead controls |
