## What Was Built

**NamerStylePostMath** (Editor/Stylize/NamerStylePostMath.cs): every operator of URP's LDR grading path that the fit needs to predict, ported from the installed core RP source with named constants citing file:line — ParamsLogC (LinearToLogC / LogCToLinear via `exp10`), LIN_2_LMS / LMS_2_LIN CAT02 matrices, `unity_to_ACES` (mul by sRGB_2_AP0; **no** 1.0/0.6 scaling — see deviations), the full `AcesTonemap` port (Rgb2Saturation, Rgb2Yc, Rgb2Hue/CenterHue, FastSign, SigmoidShaper, GlowFwd, RRT+ODT desat matrices, DarkSurroundToDimSurround with the xyY third slot carrying Y, D60→D65→Rec709), `TonemapLdr = saturate(AcesTonemap(UnityToAces(c)))`, `Luma709`, and `kAcesCcMidGray` (ACEScc encode of 18% gray, pinned by test).

**NamerStylePostFit** (Editor/Stylize/NamerStylePostFit.cs):
- `NamerStylePostFitParams` — public DTO mirroring the Volume knobs (Temperature, Tint, PostExposureEv, Contrast, Saturation, BloomThreshold, 4 × Keyframe[9], Fingerprint).
- `NamerStylePostStats` — internal accumulator: weighted RGB/luma/chroma means (doubles) + 256-bin histograms. `AccumulateSource` maps through TonemapLdr first (matching what the uber pass grades); `AccumulateReference` decodes sRGB pixels via `NamerStyleExtractor.SrgbToLinear` and bins Max3 in raw sRGB (matching how a reference PNG is consumed). Non-finite pixels are skipped in both (threat T-05.1-01-01).
- `Fit` — deterministic pipeline: WB (target gains `LinearToLms(refMean)/max(LinearToLms(srcMean), eps)`, geometric-mean normalized, recovered by a 32-sweep × 24-probe alternating-axis golden-section solve over Temperature/Tint, clamped ±100) → EV (log2 luma ratio, ±10) → Contrast (LogC p90−p10 spread ratio vs ACEScc-midgray pivot, ±100) → Saturation (chroma ratio with deadband, ±100) → curves (luma CDF matching to master keys; R/G/B composed through the master inverse, running-max, clamped [0,1]) → BloomThreshold (weighted 0.95 percentile of the reference Max3 histogram).

**Tests** (20 total, all passing):
- NamerStylePostMathTests (11): LogC round trip, absolute goldens (0.391007035 / 0.568781574 / 0.151117245), unclamped branch at x=0 (0.064037705), LMS round trip, gray→D65-direction golden (0.474636160, 0.517685675, 0.543687100), TonemapLdr unit range, per-channel monotonicity, gray-in-gray-out (spread ≤ 2e-4), absolute triple (0.20396616, 0.38009362, 0.51751275), Luma709(white)=1, kAcesCcMidGray=(log2(0.18)+9.72)/17.52.
- NamerStylePostFitTests (9): determinism (exact double-run), identical-pair neutrality, uniform-gain→EV (log2(1.6)), contrast spread recovery, WB cast recovery (coefficients pinned as goldens, recovered 20.00/−5.00 within ±0.5), saturation chroma-ratio, bloom percentile (0.701171875 midpoint), master-curve gamma pair, reference weight merging.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] unity_to_ACES carries no 1.0/0.6 scaling**
- **Found during:** Task 1
- **Issue:** Plan described the URP `unity_to_ACES` as scaling by 1/0.6; the installed ACES.hlsl:160-170 has no such factor.
- **Fix:** Port matches the source verbatim (`mul(kSrgb2Ap0, x)`, documented in-code); goldens derive from the source-accurate form.
- **Files modified:** NamerStylePostMath.cs
- **Commit:** 14c47eb

**2. [Rule 2 - Missing critical functionality] Non-finite pixel handling (threat T-05.1-01-01)**
- **Found during:** Task 3
- **Issue:** Plan's threat register assigns `mitigate` for NaN/Inf pixels entering the statistics; the plan text did not spell out the accumulator guard.
- **Fix:** Both accumulators skip non-finite pixels; all divisions have epsilon floors (kStatEpsilon, kContrastDenominatorFloor) and all knobs are clamped to URP-legal ranges.
- **Files modified:** NamerStylePostFit.cs
- **Commit:** ef4be9a

**3. [Rule 1 - Bug] Saturation railed to −100 on identical gray pairs**
- **Found during:** Task 3 (float32 test execution)
- **Issue:** float32 ACES gives a gray source a mean chroma of ~3.5e-4 (matrix row-sum deviation) while an encoded gray reference decodes to exactly 0; the plain chroma ratio rails Saturation to −100 on what should be a neutral fit.
- **Fix:** `kChromaNoiseFloor = 1e-3` deadband on |refChroma − srcChroma| plus degenerate guards (src chroma ≤ eps → +100 if the reference has chroma, else 0).
- **Files modified:** NamerStylePostFit.cs
- **Commit:** ef4be9a

**4. [Rule 1 - Bug] Two derivation bugs in the float64 cross-check prototype**
- **Found during:** Tasks 2–3
- **Issue:** (a) CIExyToLMS misport — I had applied the XYZ→LMS matrix directly to (x,y), dropping Z and the xy→XYZ step (gave absurd blue gains); (b) darkSurround xyY third slot carried Z instead of Y (HLSL is `half3(XYZ.xy/divisor, XYZ.y)`). The C# port was faithful in both cases; the hand-derived golden literals were wrong.
- **Fix:** Corrected the derivations against ColorUtils.cs:48-59 and ACES.hlsl; re-pinned the TonemapLdr golden triple to (0.20396616, 0.38009362, 0.51751275) — corrected derivation now agrees with the C# float32 execution to ~1e-7. WB fixture goldens re-derived from the corrected CIExyToLMS.
- **Files modified:** NamerStylePostMathTests.cs
- **Commit:** 26aacdb
