# Phase 05.1 Plan 03: Fit Look Lifecycle Wiring Summary

**One-liner:** End-to-end explicit Fit Look — the Processor window renders the exemplar's stylized preview, reads it back, runs the plan-01 fit, writes the profile block, and regenerates the URP Volume; the inspector gains the locked P15-P20 block and Process keeps the companion Volume in sync.

## What Was Built

### Task 1 — Window fit seam (07e7dc6)

- `NamerStylePostFitRunResult` (dual-ctor, mirrors `NamerStyleExtractResult`): success carries `Params` + `ExemplarName`; failure carries `Cancelled`/`ErrorTextureName`/`NotExtracted` — no partial result ever written.
- `NamerStylePostFit.ApplyToProfile(profile, fit, exemplarName)`: writes all six floats, four curves (fresh `AnimationCurve` copies), the fit fingerprint, and the exemplar name.
- `NamerEditorWindow.RunStylePostFit(profile)`: prereq guards -> `ClampToCaps()` -> 3-stage cancellable progress run ("Reading references", "Rendering stylized preview", "Fitting parameters"): accumulate reference stats via GetPixels (isReadable pre-check + locked read-error path), force a stylized recompute through `_forceStylizeForFit` (scoped true only inside the recompute), sync `AsyncGPUReadback` of `ResolveStylizePreviewBase(_liveResult)`, then `AccumulateSource` + `Fit`.
- Host registration: `EnsureProfileEditor` casts the created editor to `NamerStyleProfileEditor` and sets `HostWindow`.
- `HasLoadableSource` internal property (selection + primary inspection non-null).

### Task 2 — Inspector block P15-P20 + W8 + user guide (8d4a647)

- `FitButtonState(profile, exemplarAvailable)` internal static pure seam + `FitLookButtonState` readonly struct: disabled with the locked not-extracted reason, disabled with the locked no-exemplar reason, else enabled (busy deliberately excluded).
- `DrawFittedPostLookBlock()` right after `DrawStatistics()`: P15 header + help line, P16 fit-source status (fitted/unfitted), P17 Fit Look button ("Fitting…" while busy) in `DisabledScope` with the verbatim CTA tooltip incl. the P20 re-fit honesty sentence, prereq reason miniLabel, Error HelpBox, P18 eight read-only rows with "—" placeholders (Tonemapping fixed ACES; Bloom Intensity the named artist knob), P19 fit-staleness Warning — all seven locked strings verified character-for-character against the UI-SPEC.
- `ResolveExemplarWindow()`: host window when it has a loadable source, else the first open `NamerEditorWindow` with one.
- `RunFitLook()`: reset state, resolve exemplar, run the seam in try/catch, branch the run-result (Cancelled/NotExtracted return; ErrorTextureName and exceptions set the locked error copy; success -> `Undo.RecordObject` -> `ApplyToProfile` -> `SetDirty` -> `NamerStyleVolumeWriter.Write` -> `PingObject`), finally `RaiseChanged(profile)` so the debounced preview sees the fit. D-01: no debounce sentence anywhere — explicit action only.
- `DescribeProfileState` W8: extracted profiles append ", post look fitted from {exemplar}" / ", post look not fitted"; unextracted branch unchanged.
- `docs/USER_GUIDE.md`: new Stylization section (Contents entry included) with the Fit Look workflow row — Extract Style Stats -> review statistics -> Fit Look -> generated `{ProfileName}_Post.asset` Volume, D-01/D-02/D-03 honesty sentences.

### Task 3 — Process hook + lifecycle tests (b5f44fa)

- `NamerProcessor.Process`: at the successful-generation tail (last statement of the outer try, after the per-material foreach), `if (styleProfile != null && styleProfile.HasPostFit) { try { NamerStyleVolumeWriter.Write(styleProfile, settings); } catch (Exception ex) { result.Warnings.Add("Post look Volume regeneration failed: " + ex.Message); } }` — the shipped bundle never desyncs from profile truth; no fit -> no Volume, zero new code paths.
- `NamerStylePostFitLifecycleTests` (6 pure EditMode tests): the three FitButtonState prereq states (locked reasons asserted verbatim), `ApplyToProfile_WritesAllFields` (real GUID-based fingerprint via a temp asset; asserts all fields, curve key VALUES, `HasPostFit`, `!IsFitStale`), `ApplyToProfile_IsIdempotentOnRefit` (second fit replaces wholesale — no key accumulation), and the three `DescribeProfileState` clauses.
