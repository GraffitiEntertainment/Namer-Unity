# Phase 05.1 Plan 04: In-Window Stylized + Post After View Summary

**One-liner:** The fourth After View lens renders the stylized NAMER with the fitted post look graded in-shader — a function-for-function twin of URP 17.0.4's LDR path (exposure, ACES, white balance, contrast, saturation, YRGB curves) composed in ForwardLit between PBR and fog, plus a three-pass pane-level bloom approximation, honest W6 fallback, and locked captions.

## What Was Built

### Task 1 — In-shader LDR post-grade twin (cd0769b)

- `NamerPostPreview.hlsl` (114 lines): `ApplyNamerPostPreview(inout half3 color)` mirrors the URP LDR grading chain step-for-step with per-step source comments — step 2 `c *= exp2(_PostExposureEv)` (UberPost ApplyColorGrading), step 3 `saturate(AcesTonemap(unity_to_ACES(c)))` (ApplyTonemap), 4a LMS white balance via `_PostLmsCoeffs`, 4b LogC contrast around `ACEScc_MIDGRAY` (0.4135884) with `_PostContrastZ`, 4e Rec.709 luma saturation with `_PostSaturationS`, 4f YRGB curves with URP's `kHalfPixel` = 1/256 pre-offsets (master `.a` then R/G/B `.r/.g/.b` off the 128x1 `_PostCurveTex` strip), 4g final saturate. Includes URP Core.hlsl + core Color.hlsl (which pulls ACES.hlsl) — nothing re-derived; URP PP Common.hlsl deliberately excluded (Varyings clash). Early-out when `_PostEnable < 0.5`.
- `NamerSurface.hlsl`: five post uniforms appended inside the single `UnityPerMaterial` CBUFFER (SRP-batcher stable) + `TEXTURE2D(_PostCurveTex)` beside the other samplers.
- `NAMER.shader`: six `[HideInInspector]` post properties (defaults = identity: enable 0, LMS (1,1,1), EV 0, z 1, s 1) and the ForwardLit-only include + compose between `UniversalFragmentPBR` and `MixFog` — the grade hits lit color, never fog/alpha, never the other four passes. Shipped runtime materials are byte-identical (enable-gated defaults).

### Task 2 — Window lens wiring W5-W8 (2ab1d66)

- W5: `AfterViewOptions` (`NAMER`, `Stylized NAMER`, `Stylized + Post`) hoisted internal and used at the popup; `kAfterViewPost = 2`; `stylizeLens` and `ComposePreviewStylization` widened so the post lens composes the stylized base; tooltip gains the locked post sentence placed before the verbatim debounce sentence.
- W6: post lens without a fit renders plain Stylized (ApplyPostLook's enable gate) + the locked Info HelpBox under the popup.
- W7: `AlbedoPreviewPostCaption` locked constant + `ResolveAlbedoPreviewCaption(afterView, out drawFlipper)` seam routing the caption row — flipper suppressed on both stylized lenses, drawn only on NAMER.
- `ApplyPreviewPostLook()` follows ALL five `ApplyDebugGates()` call sites (ResolveGeneratedPreview, RecomputePreview, metallic/emissive toggles, DrawShaderInputToggle); `ApplyPostLook(material, profile, postActive)` writes the COMPLETE table unconditionally — neutral case included (Metal silent-skip law): enable 0/1, LMS via `ColorUtils.ColorBalanceToLMSCoeffs` (the exact function URP's ColorGradingLutPass calls), raw EV, z/s = /100 + 1, curve strip bound only when enabled.
- One-slot static curve-strip cache (`GetOrCreatePostCurveTexture`): 128x1 `TextureFormat.RGBAFloat`, linear, Bilinear/Clamp (URP's LUT-builder LinearClamp fetch), keyed on profile instance ID + every curve key, released in OnDisable (T-05.1-04-02).
- `docs/USER_GUIDE.md`: After View subsection under Stylization — three entries, the albedo caption honesty, and the W6 fallback copy verbatim.
- `NamerPostPreviewTests` (5 tests): composition gate, popup table + index pin, caption seam (all three lens states), fitted full-table uniform contract (LMS parity with the URP function, z 1.25 / s 0.6 hand-computed, strip format/filter/wrap pins), and the inactive/unfitted neutral-table law (null profile, non-post lens, unfitted profile).

### Task 3 — Pane-level bloom approximation (b335cb8)

- `NamerPostBloom.shader` (155 lines, Hidden/, unlit, Cull/ZWrite/ZTest off, core RP Common.hlsl + SpaceTransforms.hlsl): Pass 0 bright-pass with URP Bloom's exact soft-knee semantics (Max3 brightness, knee = threshold * 0.5, quadratic `softness^2 / (4knee + 1e-4)`, `max(softness, brightness - threshold) / max(brightness, 1e-4)` multiplier); Pass 1 separable 9-tap gaussian along `_BlurDirection` with URP's tap weights (sum 1) and unit-texel offsets off `_MainTex_TexelSize`; Pass 2 additive composite `source + bloom * _BloomIntensity`. All half math; named constants throughout.
- `NamerPreviewRenderer`: `SetPostBloom(thresholdLinear, intensity)` arms/disarms; the chain runs after the AFTER pane cycle — Blit pane RT → bloomA (half res, Pass 0) → bloomB (H) → bloomA (V) → composite into the persistent after-pane-final RT (Pass 2) which becomes the After pane texture. Every referenced uniform set before every dispatch each frame (Metal silent-skip law); `RenderTexture.active` restored; temporaries + lazily-created material released on disable AND Cleanup. Disabled/unset state: zero RTs, zero blits, no shader load — Render byte-identical.
- `NamerEditorWindow.ApplyPreviewPostLook` funnels `_preview.SetPostBloom(BloomThresholdLinear(profile), fitted ? DefaultBloomIntensity : 0)`; `BloomThresholdLinear` is the pure helper applying `Mathf.GammaToLinearSpace` (URP PostProcessPass's render-time conversion) with the 0 sentinel for null/unfitted.
- 2 more tests: `BloomThresholdLinear_MatchesUrpRenderTimeConversion` (parity + sentinels) and `SetPostBloom_Zero_DisablesPaneBloomChain` (fresh/(0,0)/re-disable probe states).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] GraphicsFormat needed the project's dual-using idiom**
- **Found during:** Task 3 gate (headless compile, runs 1-2)
- **Issue:** The new `EnsurePostBloomTarget` declared a bare `GraphicsFormat` parameter; on 6000.0.82f1 `using UnityEngine.Rendering;` alone does not resolve it in this assembly — all four pipeline files carry `UnityEngine.Experimental.Rendering` + `UnityEngine.Rendering` together.
- **Fix:** Mirrored the dual using; also qualified the Cleanup `DestroyImmediate` call as `UnityEngine.Object.DestroyImmediate` (the renderer is a plain class, not an Object subclass, so the window's bare-call pattern does not compile there).
- **Files modified:** NamerPreviewRenderer.cs
- **Commit:** 5c2d37d

### Plan-wording Adjustments (implemented as specified in spirit, documented for the record)

**2. ResolveAlbedoPreviewCaption signature**
- **Found during:** Task 2
- **Issue:** The plan's "e.g." seam `(afterView, hasSource, hasLiveResult)` carried two dead parameters — no caption branch reads source/result state (the empty-state reasons already live in ResolveAlbedoPreviewEmptyReason).
- **Fix:** `(int afterView, out bool drawFlipper)` — exactly the behavior the plan's test name pins (post caption AND no flipper).
- **Files modified:** NamerEditorWindow.cs
- **Commit:** 2ab1d66

**3. W6 HelpBox shows only with an attached profile**
- **Found during:** Task 2
- **Issue:** The plan's condition `(styleProfile == null || !HasPostFit)` would stack the fit HelpBox under the existing attach hint when no profile is attached (two hints for one state).
- **Fix:** `lensProfile != null && !HasPostFit` — the null-profile state keeps the established attach hint; the locked copy needs a profile name anyway.
- **Files modified:** NamerEditorWindow.cs
- **Commit:** 2ab1d66

**4. USER_GUIDE "After View row" created, not updated**
- **Found during:** Task 2
- **Issue:** The plan says "update the After View row" in the established verbatim-label style, but no After View row/section existed anywhere in USER_GUIDE.md (the 05-03 W4 popup was never documented).
- **Fix:** Added an After View subsection under Stylization (three entries, caption honesty, W6 fallback copy verbatim, debounce sentence).
- **Files modified:** docs/USER_GUIDE.md
- **Commit:** 2ab1d66

**5. Curve-strip cache keyed on curve keys, not the fit fingerprint**
- **Found during:** Task 2
- **Issue:** The plan says "cached window-side from the four curves"; a fingerprint key alone misses re-fits that land on the same refs fingerprint after key edits.
- **Fix:** Key = profile instance ID + every key of all four curves (invariant-culture "R"), rebuilt on mismatch, released in OnDisable.
- **Files modified:** NamerEditorWindow.cs
- **Commit:** 2ab1d66
