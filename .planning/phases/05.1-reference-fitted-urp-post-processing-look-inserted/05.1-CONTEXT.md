# Phase 5.1: Reference-fitted URP post-processing look - Context

**Gathered:** 2026-09-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Fit the reference look's global grade into a generated URP Volume profile, applied AFTER the baked per-texel palette mapping (Phase 5 + quick 260924-hk7). The whole scene shares one coherent runtime look; nothing tone-mapped is baked into the albedo. The Processor window previews "Stylized + Post" with the same math in-shader so the look is approved without play mode.

Locked by ROADMAP §Phase 5.1 (success criteria 1–5), not re-discussed: the fit itself (white balance via von Kries, post-exposure via mean-luma EV ratio, contrast via percentile spread, saturation via perceptual chroma ratio, master/RGB curves via histogram specification), ACES tonemapping default, bloom threshold from reference highlight percentile with artist-tweakable intensity, parametric named Volume knobs (3D-LUT/ColorLookup is a plan-time fallback only), deterministic CPU editor-side fit with no new package dependencies, tests pinning the fit math on synthetic source/reference pairs.

Out of scope: baking any tone-mapped/post-processed color into the albedo or any saved texture (hard premise — this phase amends Phase 5's "saved output equals preview" invariant to "stylized textures + companion Volume profile ship; the post layer is preview-only"), hard-coded looks, new runtime dependencies.

</domain>

<decisions>
## Implementation Decisions

### Fit lifecycle
- **D-01:** The fit runs via an explicit **"Fit Look" action on the style profile** — the Extract pattern (Phase 5 D-04/D-06): never on the ~300 ms debounce, never automatically on Process. Pressing it computes all fitted post parameters and persists them on the profile.
- **D-02:** Fitted parameters live **on the `NAMERStyleProfile` as the source of truth** (serialized, so the in-window preview renders the post look without deserializing a Volume asset back — mirrors how stage settings live on the window/profile). The **Volume profile asset is generated from them** into the generated-assets directory under the existing GEN-01/GEN-03 conventions: dedicated `NAMERGenerated/` location, overwrite limited to generated assets per the existing opt-in. Re-fitting regenerates the Volume; artist hand-tweaks to a generated Volume are expected to be lost on re-fit (the profile is the truth).

### Fit source pairing
- **D-03:** **One per-profile fit, scene-coherent.** The exemplar is the object currently loaded in the Processor window when "Fit Look" is pressed: its palette-mapped stylized output is the source distribution, the style profile's references are the target. The fit locks onto the profile and applies scene-wide; pressing Fit Look again with a different object loaded replaces the fit. No per-object refit on Process (that would drift the scene look per object, against the ROADMAP goal).

### Preview integration
- **D-04:** A **new fourth After View mode, "Stylized + Post"**, renders the stylized NAMER with the fitted post math applied in-shader in the 3D After pane. Existing modes are unchanged: Original / NAMER / Stylized stay post-free. The flat 2D albedo preview stays lens-honest (no post simulation) in this phase.

### Saturation semantics
- **D-05:** Fit **plain URP Saturation** in this phase — simplest, and the in-shader preview math matches the Volume exactly. Vibrance is explicitly deferred with a split concept (see Deferred Ideas).

### Claude's Discretion
- Estimator details within the locked fit family: exact percentiles for contrast/bloom threshold, luma/chroma statistic spaces (linear vs perceptual), ACES interplay ordering (fit pre-tonemap vs iterative refinement around the tonemap), curve key counts/resolution within URP `CurveAnimation` limits, histogram-specification smoothing.
- Fit implementation layout (CPU Burst job following the `NamerAOBaker` determinism template), file placement, exact "Fit Look" button copy/placement in the profile inspector, exemplar-binding UI affordances (e.g. status line showing which object/index the fit came from), the in-shader post-preview math structure, Volume component assembly (which overrides are enabled vs neutral), test fixture design for synthetic pairs.

</decisions>

## Existing Code Insights

- `NamerStyleExtractor` — explicit deterministic Burst extraction with fixed tables: the exact lifecycle/structure the fit replicates (source: exemplar palette-mapped output; target: reference stats already extracted on the profile)
- `NamerAOBaker` + `Bake_IsDeterministic` — element-wise-identical determinism test bar for the fit math on synthetic pairs (ROADMAP criterion 5)

- `AssetGenerator` — destination folder, prefix/suffix, overwrite-generated rules for the new Volume asset

### Established Patterns
- Explicit action, never on debounce (Extract precedent) — Fit Look follows it (D-01)
- Profile as source of truth, generated assets derive and may be overwritten on regeneration (GEN-01/GEN-03) — Volume asset follows it (D-02)
- Metal unbound-property silent-skip: every constant a dispatched kernel references is set unconditionally — applies to any new preview shader uniforms
- Debounced re-Process carries preview updates; explicit actions carry extractions/fits

### Integration Points
- `NamerStyleProfile`: new serialized fitted-post block (params + fingerprint of the exemplar fit) + ClampToCaps
- `NamerStyleProfileEditor`: Fit Look action + fitted-parameter display
- `NamerEditorWindow` After View: 4th mode → preview pipeline composes stylized + in-shader post math
- Volume profile generation: new generated-asset path beside the existing material/texture generation
- Zero existing Volume/post-processing code in the package — greenfield integration against URP 17.0.4
