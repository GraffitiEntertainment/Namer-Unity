## Fit lifecycle & artifacts

| Option | Description | Selected |
|--------|-------------|----------|
| Explicit "Fit Look" action on the profile | Extract pattern — never on the ~300 ms debounce, never automatically on Process; pressing it computes all fitted post parameters and persists them | ✓ |
| Auto-fit on every Process | Fit recomputed as part of processing; no separate user gesture | |
| Params live only on the generated Volume asset | Volume asset is the truth; preview deserializes it back | |
| Params live on `NAMERStyleProfile`, Volume generated from them | Profile serialized as source of truth (preview renders without deserializing a Volume); Volume asset derives per GEN-01/GEN-03 overwrite-generated conventions | ✓ |

**User's choice:** "explicit" (fit trigger); with the lifecycle & artifacts pairing resolved as profile-as-truth + generated Volume (presented as sub-options of this area; user's one-word answer selected the explicit trigger, and the artifact model followed from it as the coherent reading)
**Notes:** Regeneration policy — re-fitting regenerates the Volume; artist hand-tweaks to a generated Volume are expected to be lost on re-fit (the profile is the truth). No auto-fit path exists at all.

## Fit source pairing

| Option | Description | Selected |
|--------|-------------|----------|

**Notes:** The exemplar is the object currently loaded in the Processor window when "Fit Look" is pressed; pressing it again with a different object loaded replaces the fit.
