# Phase 5.1 — UI Design Contract (Unity IMGUI)

> Visual and interaction contract for the reference-fitted URP post-processing look. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This project is a Unity editor plugin, not a web frontend. Web-template dimensions (spacing, typography, color) are translated into Unity IMGUI terms below, inheriting the approved Phase 5 contract (`.planning/phases/05-stylization/05-UI-SPEC.md`) verbatim — this phase extends that language, it does not invent a new one. New surface: an explicit **Fit Look** action + fitted-parameter display on the profile inspector, a 4th After View lens **"Stylized + Post"**, and a generated URP Volume asset (naming/feedback conventions only — no hand-drawn Volume UI).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Unity Editor IMGUI — shadcn gate not applicable; not a React/Next.js/Vite stack) |
| Preset | not applicable |
| Component library | `UnityEditor` built-ins: `EditorGUILayout` (Foldout, Slider, Popup, ObjectField, LabelField, HelpBox), `EditorGUI.DisabledScope`, `EditorStyles`, `GUILayout.Button` — plus URP `VolumeProfile`/`VolumeComponent` APIs for the generated asset (no UI drawing) |
| Icon library | none — the house UI is text-only (no iconography anywhere in `NamerEditorWindow`) |
| Font | Unity Editor skin default (no custom fonts; light/dark themes follow the Editor automatically) |

**Baseline (binding):** the Phase 5 contract's idiom set, now concretely in code:
- Explicit-action button idiom: `Extract Style Stats` → busy label swap `"Extracting…"`, `DisabledScope(isExtracting ‖ prereq-unmet)`, synchronous run with cancellable progress bar, `Undo.RecordObject` + `EditorUtility.SetDirty` write, Error HelpBox below (`NamerStyleProfileEditor.DrawExtractButton`, `:156-231`) — **Fit Look copies this idiom exactly**
- Read-only stats idiom: `boldLabel` header + tooltip'd `LabelField(label, value)` rows, `"—"` placeholder before data, staleness Warning HelpBox (`DrawStatistics`, `:233-258`) — **the fitted-parameter block copies this idiom**
- Lens popup idiom: `After View` `EditorGUILayout.Popup` with decision tooltip + debounce sentence, flip → `_afterView`/`_settings.AfterView` + `MarkTweaking()` + `MarkDirty()`, disabled with miniLabel reason when ungated (`NamerEditorWindow:1144-1174`)
- Caption-constant idiom: albedo preview captions are named `internal const string` fields, caption row renders ALWAYS, lens-flipper `miniButton` (`NamerEditorWindow:65-95`, `:1961-1982`)
- Attach-state line idiom: `DescribeProfileState` miniLabel honesty line (`:2028-2039`)
- Ping feedback idiom: `EditorGUIUtility.PingObject` after asset creation (`CreateAndAttachStyleProfile`, `:1899`)
- Debounce: `NamerEditorConstants.DebounceSeconds = 0.3f` — the named constant, never an inline number

**Focal point:** the `Fit Look` button closing the profile inspector's extract→fit workflow, and the `Stylized + Post` After pane approving the look without play mode. (Checker rec — Visuals dimension.)

## Spacing Scale (IMGUI translation — inherited from Phase 5, zero new exceptions)

IMGUI auto-layout owns vertical rhythm; the contract constrains the exceptions we control. All declared values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| Row spacing | platform default (`EditorGUIUtility.standardVerticalSpacing`, 2px) | All control rows — never padded manually |
| Group gap | one `EditorGUILayout.Space()` | After the Statistics block and after the new Fitted Post Look block — exactly as existing groups do |
| Foldout indent | one `EditorGUI.indentLevel++` (platform 15px — Unity-owned, declared exception) | Advanced sub-controls only (unchanged); the fit block renders at top level like Statistics |

Exceptions: none beyond the Unity-owned 15px indent level (platform constant, not ours). No new thumbnails, no new fixed-size elements this phase.

## Typography (EditorStyles roles — inherited, exactly 4 roles / 2 visual weights)

No custom fonts, sizes, or weights. Light/dark variants follow the Editor skin. Body line-height is EditorSkin-owned and non-authorable.

| Role | Style | Usage in this phase |
|------|-------|---------------------|
| Section/heading | `EditorStyles.boldLabel` | New "Fitted Post Look" block header (beside "Statistics") |
| Help/status line | `EditorStyles.miniLabel` | Fit-source status line, prereq/disabled reasons, unfitted-lens hint, attach-state fit clause, third albedo caption |
| Empty-state heading / pane caption | `EditorStyles.largeLabel` | "Before"/"After" pane captions (unchanged) |
| Body/labels/values | `EditorStyles.label` (+ `popup` for the After View popup) | Fitted-parameter rows, button labels, tooltips |

Tooltips live in `GUIContent.tooltip` only (hover), never duplicated in-panel — house rule. Fitted numeric values format `"F2"` (statistics precedent); EV/percentile-derived values may append units in the value string (e.g. `"0.32 EV"`).

### A. `NamerStyleProfileEditor` — new "Fitted Post Look" block (drawn in BOTH the standalone Project inspector and the Processor window's embedded inspector)

Placement: after the Statistics block, at the end of `OnInspectorGUI` — draw order mirrors the data flow (references → Extract → statistics → Fit).

| # | Control | Type | Behavior |
|---|---------|------|----------|

| P16 | Fit-source status line | `miniLabel` | Fitted: "Fitted from: {exemplarName} — one fit per profile; refitting with another object replaces the scene look." (D-03). Unfitted: the empty-state copy above |
| P17 | **"Fit Look"** button | `GUILayout.Button` | Disabled while `isFitting` (label "Fitting…"), when `!profile.IsExtracted`, or when no exemplar resolves — each disabled state shows its prereq reason (P-rows above). Click: synchronous, cancellable progress bar (Extract/`NamerAOBaker` precedent); computes all fitted post parameters, writes them + fit fingerprint + exemplar name onto the profile via `Undo.RecordObject`/`SetDirty`, regenerates the Volume asset, then `EditorGUIUtility.PingObject` on it. NEVER on the debounce, never automatically on Process (D-01) |
| P18 | Fitted-parameter rows | tooltip'd `LabelField` — READ-ONLY (Statistics idiom, "—" before first fit) | Rows: "Tonemapping" → "ACES (default)"; "White Balance" → temp/tint; "Post Exposure" → "{F2} EV"; "Contrast"; "Saturation"; "Bloom Threshold"; "Bloom Intensity" → value + " (tweak on the Volume)"; "Color Curves" → "master + R/G/B, {N} keys". Each row carries a decision tooltip naming the fit statistic behind it (von Kries / EV ratio / percentile spread / chroma ratio / histogram spec — ROADMAP criteria 1–2). Read-only is deliberate: the artist-tweak surface is the generated Volume (D-02), and the profile stays the regeneration truth |
| P19 | Fit staleness warning | HelpBox `MessageType.Warning` | Copy above; fires when the reference fingerprint no longer matches the fit-time fingerprint |
| P20 | Re-fit honesty | tooltip on P17 (verbatim sentence in Copywriting) | Documents the accepted Volume-overwrite loss (D-02) — notification-in-place-of-confirmation |

Exemplar resolution (P17 gate): the exemplar is the object currently loaded in the Processor window (D-03) — the embedded-inspector context's own window; when drawn standalone, any open `NamerEditorWindow` with a loadable source. No open window / no source picked / no live preview result → disabled with the no-exemplar reason. Exact resolution mechanism is planner territory; the contract is "one visible, honest source of exemplar truth".

### C. Serialization, constants, generated-asset naming

- `NamerStyleProfile`: new serialized fitted-post block (params + fit-time reference fingerprint + exemplar display name), defaults neutral (post-exposure 0, unity contrast/saturation, zero white balance — an unfitted or neutral fit ≡ no post). `ClampToCaps` sanitizes the block's floats with the ToneMatch NaN-then-clamp precedent. Old profile assets deserialize the missing block to neutral (safe no-migration).
- `NamerEditorConstants`: named constants only — e.g. `kAfterViewPost`, bloom-intensity default (`DefaultBloomIntensity`, modest nonzero — recommend 1.0; intensity is explicitly the artist knob per STYL-08), curve key-count caps. No magic numbers (house law).
- Volume asset naming/feedback (D-02, GEN-01/GEN-03 conventions): written under the configured generated-assets destination via the existing `SanitizeFileName`/prefix/suffix settings, keyed by the PROFILE name (the fit is profile-scoped and scene-wide, so it must NOT live in a per-selection subfolder), with a `_Post` channel suffix mirroring `_Base`/`_Surface`/`_Residual`: `{prefix}{SanitizeFileName(profile.name)}{suffix}_Post.asset`. Carries the `GeneratedLabel` ("NamerGenerated") so the overwrite-generated opt-in gate covers it. Exact path composition is planner-adjustable within these rules.

## Interaction Contract

| Interaction | Response | Rule |
|-------------|----------|-------|
| Fit Look (P17) | Synchronous cancellable progress bar; button disabled while running ("Fitting…"); writes profile + regenerates Volume + ping | Runs once per explicit click; deterministic CPU editor-side; never on debounce, never auto on Process (D-01) |
| Fit Look with a different object loaded | Replaces the fit wholesale (params + fingerprint + exemplar name), regenerates the Volume | One per-profile fit, scene-coherent (D-03) — no per-object refit on Process |
| After View → "Stylized + Post" (W5) | Debounced recompute; 3D After pane renders stylized NAMER + in-shader fitted post math | Preview-only lens — never writes disk, never gates Process; Original/NAMER/Stylized stay post-free (D-04) |
| "Stylized + Post" selected, no fit | Preview falls back to plain Stylized + Info HelpBox reason (W6) | Every disabled/degraded state carries a visible reason — no silent dead controls |
| Profile slider edits (P7–P11, P13, P14) | Debounced 0.3 s recompute + `Undo`/`SetDirty` + `Changed` | Unchanged from Phase 5; slider edits do NOT invalidate the fit (the fit consumes the palette-mapped output distribution, not the raw sliders) |
| Reference list edits (+/–, assign) | Immediate asset edit; no recompute | Extract staleness warning fires (existing); fit staleness warning fires independently once fitted |
| Process with NAMER | Bakes stylized textures with the attached profile; where a fit exists, ships/regenerates the companion Volume from profile truth | Phase-boundary invariant: NOTHING tone-mapped is baked into the albedo or any saved texture — "stylized textures + companion Volume profile ship; the post layer is preview-only" |
| Volume hand-tweaks (on the generated asset, outside this window) | Survive until the next Fit Look, then lost | Accepted by D-02; pre-documented on the CTA tooltip (P20). No confirmation dialog |

## Volume Asset Assembly (generated — discretion exercised per CONTEXT)

Not hand-drawn UI, but the generated asset follows naming/feedback conventions and the parametric-knobs mandate (STYL-07/08, ROADMAP criterion 3):

| Volume component | Override | Fitted (source of truth on profile) | Artist knob |
|------------------|----------|--------------------------------------|-------------|
| Tonemapping | ON | Mode = ACES (URP's parameter-free curve; the fit shapes exposure/contrast/curves around it) | mode stays ACES |
| White Balance | ON | temperature, tint (von Kries fit) | tweakable |
| Color Adjustments | ON | postExposure (mean-luma EV ratio), contrast (percentile spread), saturation (perceptual chroma ratio — plain URP Saturation, D-05) | tweakable; colorFilter stays neutral white |
| Bloom | ON | threshold (reference highlight percentile) | intensity = named-constant default, explicitly the artist control (STYL-08) |
| Color Curves | ON | master + R/G/B via histogram specification; key counts within URP `CurveAnimation` limits, capped by named constants | tweakable |

All knobs are named Volume parameters — no opaque LUT. The 3D-LUT/ColorLookup route remains a plan-time fallback only (ROADMAP criterion 3, deferred).
