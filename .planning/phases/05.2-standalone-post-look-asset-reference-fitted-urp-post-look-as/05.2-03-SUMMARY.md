# Phase 05.2 Plan 03: ToneMatch Retirement Summary

**The palette luma knob is retired end-to-end — field, UI slider, constant, kernel declaration + binding, scaling utility, Process-time Volume regeneration, and every test oracle — so palette styling transfers hue/vibrance only (StyleStrength + HueReplaceMode + smoothing) and tonality is owned exclusively by a Post Look asset at full strength (R7), with orphaned 5.1 companion Volumes left in place (R8).**

## What Was Built

### Task 1 — Palette path retirement (commit 1bc63ae)

- `NamerStyleStylization.Create` is two-arg `(profile, split)`; the ToneMatch context field, the `_ToneMatch` SetFloat binding, and `DefaultToneMatch` are gone. `Active` is the two-clause OR `(Smoothing > 0 && TriIsland != null) || (PaletteAvailable && StyleStrength > 0)`.
- `NAMERStylize.compute`: `_ToneMatch` declaration deleted; `float outLuma = srcLuma;` — output luma is the source's own; anchor.z survives only in nearest-anchor matching (luma distance for achromatic texels); the `strength <= 0` early-out stays as belt-and-braces passthrough. C# binding and kernel declaration died in the same commit (Metal unbound-property silent-skip rule).
- `NamerStyleProfile`: ToneMatch field + ClampToCaps sanitize block deleted; fitted-post fields stay until plan 06.
- `NamerStyleProfileEditor`: slider row deleted; Style Strength tooltip is the R2 verbatim palette-strength text (palette never touches tonality, a Post Look asset owns tone).
- `NamerProcessor`: 2-arg Create call site.
- Compile-forced beyond the plan's two call sites (see Deviations): `NamerEditorWindow` — ComposePreviewStylization is 3-arg, ApplyPostLook enable gates on `postActive && profile.HasPostFit` with direct field reads, pane bloom is `fitted ? DefaultBloomIntensity : 0`, curve cache key drops the tone term; `NamerStyleVolumeWriter.Write(profile)` — all writes unscaled direct reads.

### Task 2 — Scale utility deletion + R8 (commit 101aba3)

- `NamerPostLookScale.cs` (+.meta) deleted from disk via plain `rm` (untracked — nothing to stage).
- `NamerProcessor`: the Process-time companion-Volume regeneration block deleted (R8) — Process writes/refreshes no Volume; orphaned 5.1 companion Volumes are left in place, never auto-deleted.

### Task 3 — Test retirement (commit afa247a)

- Kernel tests: `Palette_ToneMatchFull_LumaSnapsToAnchor` rewritten as `Palette_ReplaceFull_LumaStaysAtSource` (new contract: full Replace ramp snaps hue, luma stays at the source's); `Palette_AchromaticTexel_MatchesByLumaNotHue` rewritten as `Palette_AchromaticTexel_FullPassthrough` (retired snap asserted by its absence — the achromatic texel keeps its own luma with the luma-nearest anchor in the set); `Create_PostOwnsTone_ZeroesToneMatchOnly` deleted; the 4-arg toneMatch `CreatePaletteContext` overload deleted; the D-02 pin `Context_IdentitySettings_InactiveAndNoMeshFlagged` retained and restructured — anchors alone never activate (tone-only dispatch path retired).
- Volume writer tests: `Write_ToneMatchZero_WritesNeutralVolume` and `Write_ToneMatchHalf_HalvesFittedParams` deleted; the fitted-profile fixture drops its tone assignment (asserts were already full-strength direct values).
- Profile tests: default assertion and `Profile_ClampToCaps_ClampsToneMatch` deleted.
- Integration tests (14th file): renamed `Stylization_PreservesAlbedoLumaStructure`, dropped the Create wiring assert, reworded comments/messages; all luma-preservation assertions unchanged.
- Hue/saturation oracles untouched; no non-retired assertion weakened.
