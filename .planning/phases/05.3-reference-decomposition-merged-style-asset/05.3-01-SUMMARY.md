# Phase 05.3 Plan 01: Inverse Grade Math Twin Summary

**One-liner:** CPU twins of the pinned URP 17.0.4 LDR grading chain with five deterministic inverses and a fixture-defined neutral source — chain de-grade round-trips worst-case knobs to 2.2e-5 via a Newton-refined tonemap inverse.

## What Was Built

### Task 1 — `NamerStyleGradeMath.cs` (commit d79e63d)

- **Forward twins** transcribing `NamerPostPreview.hlsl:55-112` stage-for-stage (10 file:line citations): `ForwardExposureTonemap` (EV scale + `TonemapLdr`), `ForwardWhiteBalance` (calls engine `ColorUtils.ColorBalanceToLMSCoeffs` directly — never transcribed, never knob-negated), `ForwardContrast` (LogC pivot z-map), `ForwardSaturation` (input-Luma709 pivot), `ForwardCurves` (YRGB with both 1/256 half-pixel pre-offsets, evaluated exactly as the window bakes the 128-texel strip), and the composed `ForwardGrade` with final saturate.
- **Inverses** (D-02: invert the estimator family's own chain, no second estimator family): `InverseCurves` (reuses the widened `NamerStylePostFit.MasterInverse` verbatim over the 9-key uniform grid), `InverseSaturation` (fixed-point, luma-preserving map converges in one step, s ≤ 0 pass-through), `InverseContrast` (closed form, z ≤ 0 pass-through), `InverseWhiteBalance` (LMS division by the forward coefficients), `InverseExposureTonemap` (radial 48-law bisection seed + 4 fixed-count finite-difference Newton refinements, Cramer solve, singular-Jacobian deterministic stop, bracket clamp), and the composed `DeGrade` in reverse order over `ClampEffectiveKnobs` (T/Tint ±50, EV ±10, contrast/saturation ±100 — STYL-14).
- **Neutral source** (RESEARCH Open Question 1 resolution): `BuildNeutralSourcePixels` — 16×16 grid, EV-ladder luma columns anchored at `kNeutralMidGrayLinear = 0.18f`, half achromatic rows + half canonical-chroma hue cycle, normalized so the raw luma mean is exactly 0.18; `BuildNeutralSourceStats` runs the shipped `AccumulateSource` verbatim so every anchor is derived, never hand-picked.
- **`NamerStylePostFit.cs` change:** `MasterInverse` private→internal only (doc cites the `EvaluateRefitMaxError` widening precedent).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Tonemap inverse: radial-only design could not meet the round-trip acceptance criterion**
- **Found during:** Task 2 golden derivation (measurement harness, before committing Task 1)
- **Issue:** The plan sketched `InverseExposureTonemap` as radial bisection on y's ray. `TonemapLdr` is cross-channel (ACES glow module, red modifier, RRT/ODT desaturation), so the true pre-tonemap point does not lie on y's ray: measured error 0.13 at chroma 0.15, 0.32 at 0.3, **0.74 at 0.5** — and the whole-chain error 0.226, versus the plan's own whole-chain round-trip acceptance criterion. The plan's per-stage sketch and its Task-2 acceptance were mutually unsatisfiable.
- **Fix:** Kept the radial bisection as the initial guess (scale + direction seed) and added exactly `kTonemapNewtonIterations = 4` finite-difference Newton refinements on the output-space residual, treating the shared `TonemapLdr` as a black box (3×3 Jacobian by forward differences at `kTonemapJacobianStep = 1/1024`, Cramer solve, iterate clamped to the bracket, deterministic stop on a singular Jacobian). No ACES constant is re-transcribed (transcription law intact); fixed counts and strict `<` comparisons preserve the determinism contract.
- **Result (measured):** tonemap inverse worst 4.8e-6 (chroma ≤ 0.5, EV ∈ {0,±2}), 1.4e-4 at EV ±5 near the shoulder (documented best-effort class); whole chain worst-case knobs d1 2.2e-5 / d2 1.4e-5. `kRoundTripTolerance = 1e-3` holds with ≥7× headroom.
- **Files modified:** NamerStyleGradeMath.cs
- **Commit:** d79e63d

**2. [Rule 1 - Bug] Neutral fixture normalized the raw luma mean to 1.0 instead of 0.18**
- **Found during:** Task 2 golden measurement
- **Issue:** `BuildNeutralSourcePixels` divided by the computed mean, so the raw mean luma was 1.0 — breaking the plan's normalization contract ("raw luma mean of the whole grid is exactly kNeutralMidGrayLinear") and the kNeutralMidGrayLinear provenance that makes the shipped EV bisection absolute.
- **Fix:** Divide by `mean / kNeutralMidGrayLinear`; measured raw mean luma now pins 0.18 (within 6e-8).
- **Files modified:** NamerStyleGradeMath.cs
- **Commit:** d79e63d

**3. [Rule 2 - Missing guard] `InverseContrast` z ≤ 0 pass-through**
- **Found during:** Task 1 implementation
- **Issue:** contrast = −100 makes z = 0; the closed-form inverse divides by z. The plan specified the degenerate pass-through guard only for saturation.
- **Fix:** z ≤ 0 passes the input through unchanged (documented: the forward map collapses onto the pivot constant — nothing to invert; pinned by `ForwardContrast_MinusHundredCollapsesToPivotLinear`).
- **Files modified:** NamerStyleGradeMath.cs
- **Commit:** d79e63d

**4. [Rule 2 - Completeness] `ClampEffectiveKnobs` also clamps contrast/saturation to ±100**
- **Found during:** Task 1 implementation
- **Issue:** The plan text named only T/Tint (±50) and EV (±10) for the defensive clamp; contrast/saturation mirror `kParamRangeLimit` (NamerStylePostFit.cs:203) and out-of-cap percent knobs would otherwise forward/invert differently than the render applies (STYL-14 law).
- **Fix:** Contrast/saturation clamp to ±100 with the `:203` citation. Pinned by the clamp-effective equality test (±300 over-cap == capped, bitwise).
- **Files modified:** NamerStyleGradeMath.cs
- **Commit:** d79e63d

**5. [Plan reconciliation] `AnimationCurve MasterCurve` sketch vs shipped `Keyframe[] MasterKeys`**
- **Found during:** Task 1 implementation
- **Issue:** The plan's interface sketch carried `NamerStylePostFitParams.MasterCurve` (AnimationCurve); the shipped class stores `MasterKeys` (Keyframe[]).
- **Fix:** `ResolveMasterCurve(p)` builds `new AnimationCurve(p.MasterKeys)`; null/empty keys resolve to the identity diagonal. Documented in `ForwardGrade`'s contract comment.
- **Files modified:** NamerStyleGradeMath.cs
- **Commit:** d79e63d

**6. [Test tolerance derivation] WB neutral-knob identity tolerance is 1e-4, not 1e-6**
- **Found during:** test execution (16/17 first run)
- **Issue:** The engine's own `ColorBalanceToLMSCoeffs(0,0)` is (1.00000036, 0.9999993, 1.00000346) — not exactly unit — and the shader path consumes those same coefficients; through the LMS round trip the deviation reaches 6.0e-6. The twin faithfully mirrors the shader; an exact-identity bar was mis-derived, not the code.
- **Fix:** Identity assertion tolerance set to `kGoldenTolerance` (1e-4) with the measured derivation in the comment (real knob-map drift is ≥1e-2 and still fails loudly).
- **Files modified:** NamerStyleGradeMathTests.cs
- **Commit:** c34308f
