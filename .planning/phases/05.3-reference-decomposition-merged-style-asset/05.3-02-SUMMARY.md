# Phase 05.3 Plan 02: Merged Style Asset Foundation Summary

**One-liner:** The merged `NamerStyleAsset` — ONE shared weighted list, the re-homed post block, the palette block, sliders, and decomposition/validation state behind three INDEPENDENT flags — is creatable only via `Assets/Create/NAMER/Style`, generates its own Volume through an extracted shared-write core, and attaches through a dedicated `StyleAssetGuid` pref that never reads the legacy profile pref.

## What Was Built

### Task 1 — `NamerStyleAsset.cs` + constants + menu M1 + legacy retirement M2/R4 (commit 96551cf)

- **State model (D-05/STYL-15):** ONE `References`/`ReferenceWeights` pair (declared exactly once — no second list anywhere in the file), the NamerPostLook Post* block re-homed field-for-field (identical names, defaults, `CreateNeutralCurve` initialization), the NamerStyleProfile palette block verbatim plus `PaletteSourceAtExtract`/`PaletteSource` (the S12 AtExtract twin), the five sliders + `HueMode`, and the decomposition state (`DecompositionFingerprint`, `GradeSourceExemplarName` S6 honesty pair, `ConfidentAlbedoFraction`/`ContaminatedFraction` at -1 = never-decomposed) + validation state (`ValidationResult`/`ValidationFingerprint`).
- **Three INDEPENDENT flags:** `IsDecomposed`, `HasFit`, and palette-present (`PaletteAnchors.Count > 0`, deliberately no separate bool — no combined flag exists). Staleness seams compose the NamerPostLook way: `IsDecompositionStale` (fingerprint compare), `IsPaletteSourceStale` (AtExtract compare, only once decomposed), `IsVolumeStale` (params fingerprint incl. curve keys, only once fitted).
- **Machinery copied verbatim-in-shape:** `CreateNeutralCurve`, `AssignedReferenceCount`, `ComputeFingerprint` (GUID:weight "R" pipes), `ComputeParamsFingerprint` + `AppendCurveKeys`, `ClampToCaps` extended to the merged surface — list truncation/weight sync, NaN-then-clamp on every Post float, sliders (NaN → each slider's default, then its Range clamp), `PaletteSourceAtExtract`/`PaletteSource` clamped to [kPaletteSourceDeGraded, kPaletteSourceRaw], confidence fractions (NaN → -1 sentinel, then [-1,1]), `SanitizeCurve` × 4.
- **`Changed` event** declared (plan 06 lands the `RaiseChanged` partial) under a transient `#pragma warning disable CS0067` so the assembly stays warning-clean.
- **Menu M1:** `[MenuItem("Assets/Create/NAMER/Style")]` + `ProjectWindowUtil.CreateAsset(..., NamerEditorConstants.StyleAssetDefaultAssetName + ".asset")` — composed constant, never an inlined literal.
- **Menu retirement M2/R4:** the `Assets/Create/NAMER/Style Profile` and `Assets/Create/NAMER/Post Look` blocks deleted compile-atomically; both asset classes and their editors stay (migration sources).
- **Constants (wave-1 landing):** `StyleAssetDefaultAssetName = "New Namer Style"`, `kPaletteSourceDeGraded = 0`, `kPaletteSourceRaw = 1`, `DefaultPaletteSource`, and `kValidationMismatchThreshold = 0.10f` (doc names plan 03's `NamerStyleDecomposer.ComputeValidationMeasure` as consumer — wave 2 never edits the shared file).

### Task 2 — Volume writer merged-asset overloads (commit 6cb0368)

- `ComposeVolumePath(NamerStyleAsset, …)` (name-keyed on the MERGED asset's name; doc cites the 05.2 R8 orphaned-Volume precedent — the old look-keyed Volume orphans in place, never deleted silently), `PreflightWriteGate(NamerStyleAsset, …)` (internal), `Write(NamerStyleAsset, …)` (public, returns VolumeProfile).
- **Pure extraction:** the Volume-assembly body now lives exactly once in the private `WriteVolumeAtPath` (fresh VolumeProfile per write, Tonemapping(ACES)/White Balance/Color Adjustments/Bloom/Color Curves wiring, sub-asset parenting, SaveAssetIfDirty, Load-verify-throw-BEFORE-stamp, AssetGenerator.Stamp, then the caller's fingerprint stamp). Both public overloads are thin shells; the `NamerPostLook` overload's behavior is unchanged. `ComposeVolumePathFromName` and `PreflightWriteGateAtPath` give the path formula and gate discipline one home each.

### Task 3 — `StyleAssetGuid` pref + `ResolveStyleAsset` + sandbox mirroring + tests (commit f757c23)

- `NamerProcessorSettings.StyleAssetGuidKey = "NamerProcessor.StyleAssetGuid"` + the `StyleAssetGuid` property mirroring `PostLookGuid` exactly; `StyleProfileGuid` untouched (A9 — detaches by no longer being read).
- `NamerProcessor.ResolveStyleAsset` (internal static) mirroring `ResolvePostLook` field-for-field (empty GUID → null; unresolvable path → null; wrong type → null silent detach). `Process` untouched — diff verified purely additive (+29/-0); plan 05 owns the composition switch.
- **Sandbox mirroring (04.3 lesson):** the `"NamerProcessor.StyleAssetGuid"` literal added to the snapshot/restore key list of all five pref-isolation files — NamerProjectionAcceptanceTests, NamerRoughnessFitTests, NamerAOUnmultiplyRoundTripTests (the minimal 3-key sandbox extended in its own shape), NamerOneTextureTests, NamerStylizationIntegrationTests.
- **`NamerStyleAssetTests.cs` (12 tests):** fresh-instance neutrality over every block; the no-conflation migrated-state pin (palette-present && `HasFit` && !`IsDecomposed` simultaneously, plus the honest volume-stale-until-first-merged-write pin); the NOT-STALE-AFTER-DECOMPOSE pin (bare `ComputeFingerprint()` write → not stale; weight change → stale; ASSIGNED reference change → stale — null slots deliberately skipped); `IsPaletteSourceStale` flip semantics; ClampToCaps (NaN-then-clamp ordering, weights truncation, degenerate-curve reset, slider NaN→default, palette-source clamp, confidence-fraction clamp + NaN→-1); fingerprint determinism/sensitivity (both fingerprints); `IsVolumeStale` drift; and the three `ResolveStyleAsset` tests (empty GUID → null, resolves a temp-folder asset by GUID, wrong-type path → null) with temp-folder + pref snapshot/restore in `finally`.

**2. [Rule 2 - Completeness] ClampToCaps extends NaN-then-clamp to the slider group**
- **Found during:** Task 1 implementation
- **Issue:** The plan's ClampToCaps spec says "NaN-then-clamp on every float" but enumerates only the NamerPostLook donor floats + the new fractions. The merged asset additionally owns the five serialized palette-application sliders — leaving them unsanitized would admit hand-edited NaN/out-of-range values into the bake path (T-05.3-02-01 mitigation is "sanitize-before-read at every consumer").
- **Fix:** Each slider: NaN → its `NamerEditorConstants` default, then clamp to its own [Range] bounds (CavityFloor to [0,0.5], matching the attribute). Pinned by `Asset_ClampToCaps_SanitizesPostBlockSlidersAndWeights`.
- **Files modified:** Packages/com.graffitientertainment.namer/Editor/Stylize/NamerStyleAsset.cs
- **Commit:** 96551cf

**3. [Rule 2 - Warning-clean law] Transient CS0067 pragma on the plan-mandated `Changed` event**
- **Found during:** Task 1 compile
- **Issue:** The plan mandates declaring `NamerStyleAsset.Changed` now (raisers/subscribers land in plans 04/06), but an unused field-like event emits CS0067 — violating the project's compile-without-warnings gate.

**4. [Build plumbing, not a code change] csproj compile-list additions for the two new files**

**5. [Test misencoding — found by the wave-1 live EditMode gate] `Asset_IsPaletteSourceStale_FlipsOnlyOnSourceMismatch` simulated decomposition on an EMPTY reference list**
- **Found during:** post-plan live gate (full suite 342 passed / 1 failed — the only failure)
- **Issue:** The test wrote `DecompositionFingerprint = ComputeFingerprint()` on an asset with zero assigned references; `ComputeFingerprint()` over an empty list returns the **empty string**, which is exactly `IsDecomposed`'s never-decomposed sentinel (`!string.IsNullOrEmpty`). So `IsDecomposed` stayed false and `IsPaletteSourceStale = IsDecomposed && PaletteSource != PaletteSourceAtExtract` read false at the `IsTrue` assertion (Expected True, was False). The earlier assertions passed only vacuously, and the "matching sources" step also never set `PaletteSourceAtExtract` to the source the simulated Decompose used (masked by the same never-decomposed state). The production seam is verbatim-correct per plan Task 1 ("IsDecomposed (non-empty DecompositionFingerprint)", "IsPaletteSourceStale (IsDecomposed && PaletteSource != PaletteSourceAtExtract)") — a decomposed asset by definition consumed the shared list, so the simulation must too.
- **Fix (test only, no production change):** add an assigned reference + weight so the bare fingerprint write is non-empty, set `PaletteSource`/`PaletteSourceAtExtract` to the de-graded source the simulated Decompose used, and add an `IsDecomposed` sanity assert so this class of misencoding can never silently recur.
- **Files modified:** Packages/com.graffitientertainment.namer/Tests/Editor/NamerStyleAssetTests.cs
- **Commit:** 635ef16
