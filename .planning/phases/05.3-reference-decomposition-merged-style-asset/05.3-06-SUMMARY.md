# Phase 05.3 Plan 06: Merged Style Asset Editor Summary

**One-liner:** The merged `NamerStyleAsset` now has its own custom inspector — one shared weighted reference list feeds an explicit Decompose Style transaction (exemplar-refined, preflighted, single Undo group) that fills the palette, confidence stats, fitted post look, and companion Volume; everything is tweakable afterwards (S14 debounced sliders, S15 carried post block, S16 Volume), and Validate Look ships the STYL-17 forward-validation evidence surface — with the USER_GUIDE collapsed to the single Style Asset workflow.

S1-S5 reference section (empty-state, 64px material-inspector slot rows, +/– footer with copy-locked tooltips, count line carrying the min-3 clause, Advanced foldout with per-reference decomposition weights + Hue Mode); S6-S8 Decompose block (status line naming the weighted count — and the exemplar when the D-02 refinement engaged —, the button with its single prereq, the failure HelpBox); S9 confidence stats rows (em-dash before first decomposition, whole percent after); S10 staleness Warnings (palette source / references); S11-S13 palette block (extraction-variant state line, Palette Source popup as input for the NEXT decomposition, read-only HSL rows over the raw LinearColor).

## Deviations from Plan

### Auto-fixed Issues

**1. [Result-shape] Stats not written by RunDecompose**
- `NamerStyleDecomposeResult` has no Stats field (deliberate plan-03 shape); S9 renders only the two confidence rows. No consumer exists for a stats block on the merged asset (the profile editor's Statistics block was retired in 05.3-05 R7).

**2. [Out-of-files-list edits, plan-sanctioned]**
- `NamerStyleAsset.cs`: the CS0067 pragma removal was explicitly promised by the field's own comment ("remove this pragma with it") and the 05.3-05 Deferred Items.
- `NamerStyleDecomposer.cs`: `CountPositiveWeightReferences` widened private → internal (the EvaluateRefitMaxError seam-widening precedent) — one honest counter shared by the gate seam and the status line, no duplicate.

**3. [Constants placement] Legacy editors keep their inline copies**
- The carried S15/S16 5.2 copy lives in NamerEditorConstants for the merged editor while the legacy `NamerPostLookEditor` keeps its frozen inline strings — those files are out of this plan's files_modified and are migration-source surfaces (the deferred UI-SPEC checker pass covers them).

**4. [Copy adaptations, within the spec's adapter latitude]**
- S5 weight tooltip: the D-05 fit copy adapted to decomposition wording, without the profile editor's debounce suffix (weights apply at decompose time; they never recompute anything).
- S17 not-extracted detail message under the locked failed wrapper is adapter-composed (the UI-SPEC locks only the wrapper sentence).
- S13 palette swatch displays the raw `anchor.LinearColor` (data display — no invented gamma conversion; the HSL text carries the numbers).

**5. [Guard addition] Validation-stale line requires a non-empty `ValidationFingerprint`**
- The plan's literal condition would render "Validation stale" on every never-validated decomposed asset (empty stamp ≠ a stamp). The guard implements the locked copy's own "since the last validation" presupposition.

**6. [Sequencing] RunDecompose's Volume-write failure surfaces through decomposeError**
- Rendered by the S8 HelpBox at Task 1 close (no read-before-Task-2 warning window); the same locked copy constant serves both surfaces.
