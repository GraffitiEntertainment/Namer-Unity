**Defined:** 2026-09-29, via `/gsd-ingest-docs --mode merge` of `.planning/research/style_extraction.md` (classification `style-extraction-00002268.json`, DOC / medium confidence / unlocked). Conflict report: `.planning/INGEST-CONFLICTS.md`. Synthesis: `.planning/intel/`.

**Origin idea:** Reference screenshots already carry lighting + post. Before extracting a palette, estimate the grade (exposure, white balance, tone curve, contrast, saturation, bloom) and classify pixels so the palette comes from de-graded base colors (raw screenshot orange `#E58B48` may really be base asset color `#A96742` — `#A96742` is what belongs in vertex colors). This is the inverse of what NAMER already does to assets: separate what belongs to the scene from what belonged to the material. Model-free — reuse/invert the existing fit math.

## Implementation Decisions

### Pipeline position
- **D-01 (UPHOLDS 05-CONTEXT D-01):** Palette mapping stays pre-fit — albedo texels remap to their closest HSL-palette entry, THEN the VC fit runs on the remapped albedo ("stylize the source, then fit"). The ingest doc's post-fit OKLab VC remap is rejected-for-now; re-openable only with 05.3 evidence (e.g. if the remapped albedo degrades residual coverage, per the D-13 one-texture path where VCs are the sole color carrier). Hue identity (STYL-03) and no-luma-transfer (STYL-11) stay pinned either way.
- **D-02:** Decomposition consumes/inverts the `NamerStylePostFit` estimator family (von Kries WB, mean-luma EV, percentile contrast, perceptual chroma saturation, histogram curves, bloom percentile). Model-free estimation is primary; the 05.2 D-04 delta-fit from the window's forced-stylized render is retained as a fallback/complement. No second estimator family.
- **D-03:** LUT stays plan-time fallback only (locked 5.1 decision — parametric named Volume knobs). The doc's `ReferenceStyleLUT` idea survives only as the analysis-side `colorTransform` estimate, not as an output asset. Visible forward-validation mismatch (STYL-17) is the unlock condition for revisiting.

### Palette source
- **D-04:** Palette source = de-graded base colors by default; raw-pixel (shipped STYL-02 behavior) behind a switch. Acceptance criterion: inverse-consistency with the fitted post look — the grade is applied exactly once (de-grade at extract OR Volume at render), never doubled.

### Asset shape
- **D-05 (SUPERSEDES 05.2 D-03/D-05):** ONE merged style asset: ONE shared weighted reference list, ONE editor. The decomposition splits that list into (a) the palette block — an HSL color list from the de-graded base colors — and (b) the fitted post block — from the grade estimate. 05.2 D-06 (per-asset Volume generation under GEN-01/GEN-03) and D-04 (fit-from-window-render seam) carry over. Migration merges existing `NamerStyleProfile` + `NamerPostLook` assets losing neither extracted palettes nor fitted looks (05.2 D-07's no-silent-loss rule applies to the merge).
- **D-06 (NEW, user-directed 2026-09-29):** Creation is **menu-only** (`Assets/Create/NAMER/…`). The NAMER Processor panel NEVER creates the asset — it exposes only a load/use object field (asset picker), replacing the panel-side "Create Post Look…" / "Create Profile…" pattern. Fitting, extraction, and hand-tweaking live in the asset's own inspector.

### Contamination
- **D-07:** Confidence-mask down-weighting during palette extraction: bloom, specular highlights, emissive pixels, deep shadows, clipping, fog, and transparent effects get zero/low weight so the palette estimates what the artist put in the material.
