## Summary

This phase inverts an estimator family the project already ships. `NamerStylePostFit.Fit(source, reference)` computes every knob as a statistic ratio of reference-over-source (von Kries gains on LMS means, mean-luma EV bisection through `TonemapLdr`, LogC p90/p10 spread ratio, mean-chroma ratio, master-curve histogram specification, p95 bloom cut) — so the model-free decomposition with no "from" render reduces to **calling the shipped `Fit` verbatim with a synthetic NEUTRAL source distribution** (a deterministic canonical "un-graded render": mid-gray mean, named neutral spread/chroma anchors, uniform post-tonemap histogram). That is the strongest possible reading of D-02: the same code path, only the source-stats constructor is new. White balance then degenerates to classical gray-world von Kries on the confidence-weighted reference mean — a 40-year-standard estimator [CITED: staff.science.uva.nl/pub/GeversTIP07.pdf].

The per-pixel de-grade operator inverts the project's own pinned forward chain. `NamerPostPreview.hlsl:55-112` mirrors URP 17.0.4's LDR grading chain step-for-step with file:line citations (verified against the installed PackageCache sources: `Common.hlsl` `ApplyColorGrading`/`ApplyTonemap` + `LutBuilderLdr.shader` `FragLutBuilderLdr`): `·2^EV → saturate(AcesTonemap) → LMS WB → LogC contrast → linear saturation → YRGB curves → saturate`. Every LUT stage has a closed-form or table-exact inverse (contrast is affine in LogC around `kAcesCcMidGray`; WB is per-channel division by `ColorBalanceToLMSCoeffs(T,Tint)` in LMS; curves invert via the shipped `MasterInverse` discipline; saturation inverts by a small fixed-count fixed-point solve). Only the tonemap+EV pair needs a numeric inverse — a radial bisection licensed by the shipped monotonicity comment ("TonemapLdr is monotone in uniform scale", `NamerStylePostFit.cs:342-344`), using the existing 48-fixed-iteration determinism precedent. Clipped and near-black pixels are NOT invertible — and they are exactly the D-07 contaminated classes, so the confidence mask and the inverse's domain gaps cover each other by construction.

The merged asset is a serialization re-home of two shipped assets plus decomposition outputs; the critical planning trap is the **state model**: STYL-15's no-silent-loss law plus UI-SPEC M3's "decomposition does NOT auto-run" mean the migrated palette (from profile) and fitted post block (from look) must survive on an asset whose `IsDecomposed` flag is still false — three INDEPENDENT flags, not one. STYL-16 is nearly free: the stylize stage already runs pre-fit (stage 3 of `NamerStylizePipeline.Run`, before the VC fit consumes the dst), and `CSPaletteTransfer` already does nearest-anchor matching with strength scaling and never transfers luma — retargeting the anchor data source at the merged asset's de-graded HSL palette satisfies the requirement with zero new GPU surface.

**Primary recommendation:** Build in this order — (1) CPU twin of the four LUT stages + their inverses (golden-tested, house `NamerStylePostMath` transcription law), (2) neutral-stats constructor + `Fit` reuse + de-grade operator with round-trip pins, (3) two-pass classification/decompose over cached downsampled references, (4) merged asset + Volume writer retarget + menu, (5) merged editor + window W15–W18 + retirements, (6) merge dialog, (7) STYL-16 data retarget + Validate Look. No new packages, no new compute kernels, no new estimator family.

### Pattern 1: Decomposition = `Fit` with a synthetic NEUTRAL source (D-02's strongest form)

**What:** Every estimator in `NamerStylePostFit.Fit` is a ratio `stat(reference) / stat(source)`. With no rendered "from" end, construct a deterministic synthetic NEUTRAL source distribution — the canonical "un-graded render" — and call the shipped `Fit(neutralStats, referenceStats, fingerprint)` verbatim.

**Why it satisfies D-02:** zero new estimator code paths; the only new math is the neutral-stats constructor (named constants, fixed histograms). WB degenerates to gray-world von Kries on the confidence-weighted reference mean (`gains = GeoMeanNorm(refLms / Lms(gray))` — because the source LMS mean is uniform gray, the shipped geometric-mean normalization makes the source term vanish except for scale) [CITED: Gevers & van de Weijer TIP 2007, staff.science.uva.nl/pub/GeversTIP07.pdf — gray-world = L1 Minkowski statistic family]. EV becomes the closed bisection target `TonemapLdr(kNeutralMidGray · 2^EV).luma = refMeanLuma` — literally the shipped bisection loop with `srcRawMean = 0.18f` (ACES mid-gray, matching `kAcesCcMidGray` provenance). The master curve with a uniform source histogram returns `y = F_ref⁻¹(x)` — the reference's own inverse CDF, which is exactly the tone-curve un-map under a uniform-neutral assumption.

**Neutral anchors needing named constants (see Assumptions A1/A2):**
- `kNeutralMidGrayLinear = 0.18f` (ACES mid-gray; existing provenance comment at `NamerStylePostMath.cs:39-41`)
- Neutral LogC p90−p10 spread (contrast anchor) — options: (i) a fixed canonical constant, (ii) 0 (grade never de-contrasts — conservative), (iii) the spread `TonemapLdr` induces on a defined neutral ramp. Recommend (i) with a round-trip-pinned constant; the synthetic-fixture test makes any choice self-consistent.
- Neutral mean chroma (saturation anchor) — same structure; note the shipped saturation is floored at 0 (never desaturates), so the de-grade's saturation inverse only needs to undo boosts.

**When to use:** the primary Decompose path (reference-only, no exemplar prereq — S7). The 05.2 D-04 window-render delta-fit survives as the named complement/refinement (S6 "refined against {exemplarName}" honesty line) — run `Fit(windowRenderStats, referenceStats)` AFTER the neutral estimate and prefer/compose per planner's discretion; UI-SPEC requires the engaged variant be NAMED, never silent.

### Pattern 2: Two-pass decompose over cached downsampled buffers

**What:** Pass 1 reads each reference once (extractor discipline: `isReadable` pre-check, one at a time, buffer dropped), box-downsamples to `kExtractResolutionCap` (128), caches the downsampled arrays (≈10 × 128² × 16 B ≈ 2.6 MB — trivial), and accumulates: (a) grade stats via the Fit accumulate seam, (b) luma/Max3 histograms for percentile cuts, (c) confidence aggregates. Pass 2 applies classification weights + the inverse grade per texel and accumulates the de-graded 16³ palette histogram.

**Why two passes:** classification percentile cuts (p95 highlight, p5 shadow) and the grade estimate must exist BEFORE per-pixel weighting/de-grading. Fixed order, fixed grids, strict comparisons — `Decompose_IsDeterministic` bar (extractor `Bake_IsDeterministic` precedent).

**Required seam change (internal, minor):** `NamerStylePostFit.AccumulateReference(stats, pixels, weight)` takes one scalar weight per call. The decomposition needs per-pixel confidence multiplication — add an internal accumulate overload taking a per-pixel weight array (or fold confidence into the palette/grade passes separately). `NamerStylePostStats` fields are already `internal`.

### Pattern 3: Inverse operator inventory (the de-grade chain)

The forward chain is pinned with citations in `NamerPostPreview.hlsl:45-112` (mirroring URP `Common.hlsl` `ApplyColorGrading` + `LutBuilderLdr.shader`; postExposure multiplied before tonemap in ALL modes — `PostProcessPass.cs:1534-1536` sets `lutParams.w = 2^EV`, `Common.hlsl` `input *= postExposure` before `ApplyTonemap` in the LDR branch). The de-grade runs the INVERSE chain in REVERSE order:

| # | Forward stage (order) | Forward form (verified) | Inverse | Invertibility |
|---|----------------------|------------------------|---------|---------------|
| 1 | postExposure | `c *= exp2(EV)` (`NamerPostPreview.hlsl:67`) | folded into #2's radial solve | exact (scalar) |
| 2 | ACES tonemap + saturate | `saturate(AcesTonemap(unity_to_ACES(c)))` (`:70`) | radial bisection: find λ ≥ 0 with `TonemapLdr(λ·ĉ).luma ≈ y.luma`, ĉ = y normalized; then `c = (λ·ĉ) / 2^EV` | monotone in uniform scale (shipped comment `NamerStylePostFit.cs:342-344`); NOT invertible where clipped (saturate) — those pixels are D-07 class "clipping", masked |
| 3 | White balance (LMS) | `LmsToLinear(LinearToLms(c) * coeffs)` with `coeffs = ColorBalanceToLMSCoeffs(T, Tint)` (`:75-77`, core `ColorUtils.cs:67-82`) | `LmsToLinear(LinearToLms(c) / coeffs)` of the **clamped, effective** knobs | exact per-channel division; do NOT negate knobs (the knob→chromaticity map is asymmetric: `t1<0 ? 0.1 : 0.05`, `ColorUtils.cs:75`) |
| 4 | Contrast (LogC pivot) | `(logC − mid)·z + mid`, `z = contrast/100 + 1`, `mid = 0.4135884` (`:83-85`) | `(logC − mid)/z + mid` | exact closed form |
| 5 | Saturation (linear) | `luma + s·(c − luma)`, pivot = INPUT `Luma709(c)`, `s = saturation/100 + 1` (`:91-92`, `LutBuilderLdr.shader:116-118`) | fixed-point: `L₀ = Luma709(o)`, `i = L₀ + (o − L₀)/s`, repeat 2-3 fixed iterations | exact in the limit; small fixed count keeps determinism (the pivot is the input luma, not preserved by the map) |
| 6 | YRGB curves | master then R/G/B with 1/256 half-pixel pre-offsets (`:97-107`, `LutBuilderLdr.shader:120-138`) | invert key-monotone maps via the shipped `MasterInverse` discipline (`NamerStylePostFit.cs:598-619`), same half-pixel offsets, R/G/B (identity diagonals from the fit) pass through | table-exact for monotone curves; the fit guarantees running-max monotone keys |

**Determinism:** every numeric inverse uses fixed iteration counts and strict comparisons (the `kExposureBisectionIterations = 48` law, `NamerStylePostFit.cs:206`).

**Inverse-consistency (STYL-14/D-04):** the de-grade must invert the **effective** (post-clamp) knob values — the fitted WB clamps to ±50 and EV to ±10; the render applies the clamped values, so the de-grade divides by `ColorBalanceToLMSCoeffs(clampedT, clampedTint)` and `2^clampedEv`. Since ONE Decompose writes both blocks, palette and post block are structurally consistent; the Volume at render re-applies the forward chain to the de-graded VCs → grade applied exactly once. Acceptance test: `forwardVolume(degrade(x)) ≈ x` for unclipped synthetic pixels, and `degrade(forwardVolume(albedo)) ≈ albedo`.

### Pattern 4: Classification heuristics (D-07 / STYL-13 confidence mask)

Model-free, deterministic, on the cached downsampled grid. Each class yields a per-texel weight factor; the product with the per-reference weight feeds both the grade stats (more robust grade too) and the palette histogram. Classical basis: dichromatic model (`I = albedo·shading + specular residue`) — bright + desaturated = specular; high-percentile intensity cuts are the standard non-ML highlight detector [CITED: encov.ip.uca.fr Prokopetc et al. survey; Chhatkuli et al. 2014 HSV luma+saturation thresholding].

| Class | Cue (deterministic) | Weight | Confidence |
|-------|---------------------|--------|-----------|
| Clipping | raw sRGB max channel ≥ 1 − ε (254/255) | 0 (hard) | HIGH — also the exact non-invertible set of the tonemap inverse |
| Specular/bloom | `Max3_srgb ≥` p95 cut (the fitted bloom threshold itself — reuse `kDefaultBloomHighlightPercentile`) AND low chroma (desaturated-bright) | 0 (hard) | HIGH — reuses shipped percentile machinery |
| Emissive | above the highlight cut AND chroma ≥ threshold (saturated-bright — separates from specular) | 0 (hard) | MEDIUM |
| Deep shadow | decoded luma ≤ p5 percentile or absolute floor | 0 (hard) | HIGH (noise-dominated, non-invertible near 0) |
| Fog / atmospheric | low local luma gradient + mid-high luma + low chroma (box-gradient on the downsampled grid; in-house `RobustSobelScale` precedent for scale discipline) | low (e.g. 0.25, named constant) | LOW — most fragile heuristic; conservative low-not-zero |
| Transparency/additive veils | high luma + very low chroma + low local contrast (folds with fog class; PNG references carry no usable alpha) | low | LOW |
| Everything else (albedo/shading) | — | 1 | — |

Aggregate reporting (S9): accumulate `confidentMass`/`contaminatedMass` doubles during pass 2 → the two `"{P}%"` rows. Threshold constants are named `constexpr`-style constants (house no-magic-numbers law) and pinned by fixtures.

### Pattern 5: Merged-asset state model (the planning trap)

Three INDEPENDENT truth flags — conflation breaks either STYL-15's no-silent-loss or M3's "decomposition does NOT auto-run":

1. `IsDecomposed` (decomposition fingerprint non-empty) — false on a migrated asset until the user presses Decompose Style
2. Palette-present (HSL list non-empty) — TRUE after migration (carried from the profile), with `PaletteSourceAtExtract = Raw` (the migrated palette came from raw-pixel extraction)
3. `HasFit` (`PostFitFingerprint` non-empty) — TRUE after migration (carried from the look)

Consequences: S15's post block enables on `HasFit || IsDecomposed` (migrated fits stay tweakable); S16's Regenerate Volume enables once a fit exists (05.2 law); the S13 palette rows render whenever the list is non-empty; the S6 status line reads the honest not-decomposed copy until a Decompose runs. Defaults neutral: fresh asset = no palette, no fit, not decomposed, identity post (`NamerPostLook.CreateNeutralCurve` precedent for the diagonal).

### Anti-Patterns to Avoid

- **Negating WB knobs to invert white balance** — the knob→chromaticity map is asymmetric (`ColorUtils.cs:75`, `t1 < 0 ? 0.1f : 0.05f`); divide by the LMS coefficients instead (exact).
- **Inverting the UNclamped fit estimates** — the render applies clamped knobs (±50 WB, ±10 EV); invert the clamped, effective values or the grade doubles/mismatches (STYL-14 violation).
- **De-grading anchor COLORS after k-means instead of texels before binning** — cluster distances are computed in the graded domain; transform-then-bin is the only consistent order.
- **Per-pixel C# loops over full-res references** — the 128-cap downsample + cached buffers is the memory/determinism law (NORM-03 spirit; extractor precedent).
- **One combined `IsDecomposed && HasFit` state** — breaks migration no-silent-loss (Pattern 5).
- **Reusing `StyleProfileGuid` for the merged asset** — a stale GUID can still resolve to a live `NamerStyleProfile`; new pref field + detach/ignore of the old (04.3 sandbox-mirroring grep applies — STATE records FOUR pref sandboxes that mirror settings structs).
- **Sleep-based tests** — house law; everything here is synchronous CPU or `WaitForCompletion` readback (existing precedent).
- **Luminance-ramp classification fixtures** — flatten to zero gradient; use hash-noise grain and assert strip medians (MEMORY: NAMER test fixtures vs AO un-multiply).

## Common Pitfalls

### Pitfall 1: Double-applied grade (STYL-14's core failure mode)
**What goes wrong:** de-graded palette + the Volume both applying the grade (or neither, or the unclamped-vs-clamped mismatch) — the rendered asset looks over-graded or washed out.
**Why:** the de-grade and the forward Volume are two separately-parameterized paths over the same estimate.
**How to avoid:** ONE Decompose writes both blocks from one estimate; invert the CLAMPED effective knobs; pin `forward∘degrade ≈ identity` and `degrade∘forward ≈ identity` round-trips on unclipped synthetic pixels.
**Warning signs:** validation (S17) re-fit knobs far from identity on a synthetic self-consistent reference.

### Pitfall 2: Metal unbound-property silent skip (if any kernel/uniform roster changes)
**What goes wrong:** a dispatched kernel referencing an unset property is silently SKIPPED on Metal — exact-zero output with no error (MEMORY: Metal unbound-property silent skip).
**Why:** adding/renameing uniforms for a palette-source switch or remap mode.
**How to avoid:** prefer the zero-new-uniforms data retarget (Pattern 7); any roster change sets every argument unconditionally (`NamerStylizePipeline.cs:290-319` documents the law).
**Warning signs:** byte-zero output textures; grep Editor.log for "Skipping dispatch" before debugging math.

### Pitfall 3: RGBA32/RGBAFloat readback mismatch in validation
**What goes wrong:** `GetData<Color>` (16 B/el) against an RGBA32 request yields garbage pixels that tonemap to 0 and rail the metric (documented at `NamerEditorWindow.cs:2847-2854`).
**How to avoid:** copy the stage-2 readback discipline verbatim (`TextureFormat.RGBAFloat`).

### Pitfall 4: Saturation inverse pivot confusion
**What goes wrong:** treating URP saturation as luma-preserving and dividing `(o − luma(o))/s + luma(o)` — the pivot is the INPUT luma, which the map does not preserve; the error is second-order but compounds through the chain.
**How to avoid:** fixed-count fixed-point iteration (Pattern 3 row 5); pin with a round-trip test at |knob| = 100 (worst case).

### Pitfall 5: Migration state conflation
**What goes wrong:** a single "extracted/decomposed" flag makes a migrated asset either hide its carried palette/fit (silent loss — STYL-15 violation) or claim decomposition it never ran (dishonest S6 line).
**How to avoid:** three independent flags (Pattern 5); test both migrated-only and decomposed states.

### Pitfall 6: Determinism leaks in the new numeric loops
**What goes wrong:** data-dependent early exits, unfixed iteration counts, or per-pixel float accumulation order varying run-to-run — breaks the `Decompose_IsDeterministic` bar.
**How to avoid:** fixed counts (48-bisection precedent), strict comparisons, serial fixed-order accumulation; run-twice element-wise equality test.

### Pitfall 7: Editor project lock blocking live EditMode runs
**What goes wrong:** interactive editor holds the lock; headless batch runs fail (recurring STATE entry since Phase 01; 04.2/04.3/05.2 precedent).
**How to avoid:** compile-equivalence via Unity's bundled Roslyn against the csproj closure during execution; defer live EditMode suite to the post-wave regression gate; run live via TestRunnerApi/unity-mcp relay when available (MEMORY: live-editor EditMode test run).

### Pitfall 8: Norm violations on pref sandboxes
**What goes wrong:** adding the StyleAsset pref to the main settings struct but missing the four sandbox mirror structs — round-trip tests break elsewhere (04.3 lesson, STATE).
**How to avoid:** grep for the sandbox struct, not just plan-listed files.
