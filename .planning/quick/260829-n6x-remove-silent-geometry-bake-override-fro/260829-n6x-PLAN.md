<objective>
Remove the silent geometry-bake override from the NAMER window so that, after a
successful Process with NAMER, the first movement of any AO slider reshapes the
image-space extracted AO live — matching what `NamerProcessor.Process` writes to disk.

Purpose: The window's `TriggerAutomaticBake` auto-bakes AO from the selected game-res
mesh after every recompute and caches it in `NamerAOPipeline._bakeCache`. The three-way
AO gate then prefers that cached (near-white) geometry bake over the extracted AO, so the
live preview diverges from generated output (which never sets `BakeSourceMesh`). This is
a pure deletion: the auto-bake trigger, its dead cache-priming assignments, and the
now-orphaned "High-res Occluder" UI are removed. The bake subsystem itself
(`NamerAOPipeline`, `NamerComputePipeline` forwarders + three-way gate) stays intact as a
tested capability reserved for a future explicit opt-in "Bake AO" action.

Output: `NamerEditorWindow.cs` no longer references `TriggerAutomaticBake`,
`_occluderMesh`, or `_occluderWarning`; the preview path is a straight
`inspection` -> `_pipeline.Process(inspection)` with no bake priming.
</objective>
